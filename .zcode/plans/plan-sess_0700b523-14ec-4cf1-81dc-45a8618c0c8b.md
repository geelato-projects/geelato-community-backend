# Dao 新增显式 insert(entity) / update(entity) 能力

## 背景与结论

`dao.save(entity)` 当前语义：id 非空 → UPDATE（`WHERE id=?`），id 为空 → INSERT 并自动生成 UID。该判定在 `EntitySaveParser.parse`（geelato-core/.../meta/model/parser/EntitySaveParser.java:41）。作为框架这有局限：**无法插入一条指定 id 的数据**。由于平台约 40+ 处调用依赖现有 save 语义（BaseService.updateModel/isDeleteModel、各服务 load-modify-save 模式），save 的默认语义保持不变，**新增显式方法**（MyBatis-Plus/Spring Data 的通行做法）。

- `insert(entity)`：强制 INSERT。带 id 则保留指定 id（解决本次诉求）；id 为空仍自动生成 UID。
- `update(entity)`：强制 UPDATE。id 为空抛 `IllegalArgumentException`（fail-fast，避免静默 0 行更新）。

## 改动清单

### 1. `geelato-core/.../meta/model/parser/EntitySaveParser.java`
- `parse(IdEntity, SessionCtx)` 重构为委托 `parse(IdEntity, SessionCtx, CommandType forcedType)`（forcedType 为 null 时保持现有自动判定）。
- forcedType 为 Update 且 id 为空：抛 `IllegalArgumentException`（消息含实体名）。
- insert 分支改为：仅当 `id` 为空时才 `entity.put(PK, UIDGenerator.generate())`，使"带 id 的显式插入"保留指定 id。
- 顺带删除 47 行重复的 `setCommandType(CommandType.Update)`。
- 字段填充 SPI（`fillIfAvailable`）按实际 CommandType 触发，强制类型自然生效。

### 2. `geelato-core/.../meta/EntityManager.java`
- `generateSaveSql(entity, sessionCtx)` 委托新增重载 `generateSaveSql(entity, sessionCtx, CommandType forcedType)`，按 commandType 路由 Insert/Update SqlProvider（逻辑不变）。

### 3. `geelato-core/.../orm/Dao.java`（约 558 行处）
- 现有 `save(E)` 方法体抽取为私有 `doSave(E entity, CommandType forcedType)`；`save(E)` = `doSave(entity, null)`，对外行为零变化。
- 新增：
  - `public <E extends IdEntity> Map insert(E entity)` → `doSave(entity, CommandType.Insert)`
  - `public <E extends IdEntity> Map update(E entity)` → `doSave(entity, CommandType.Update)`
- 均带 Javadoc 说明语义（insert 保留指定 id、update 空 id 抛异常）。Save 事件链（SaveEventContext.isInsert/isUpdate 基于 command 的 CommandType）自动兼容。

### 4. `geelato-web-platform/.../srv/platform/service/BaseService.java` — 平台层迁移（行为不变或修复隐患）
- `createModel`（198 行）：`dao.save(model)` → `dao.insert(model)`。若调用方误带 id，此前是 0 行 UPDATE 静默失败，现在真正插入——属于修复。
- `updateModel`（218 行）、`isDeleteModel`（233 行）：`dao.save(model)` → `dao.update(model)`。已核实调用方（DevXxxController 的 createOrUpdate、AttachHandler 等）均在 id 非空时调用；ExportTemplate 克隆流程 setId(null) 后走 createModel，不受影响。

### 5. `geelato-web-platform/.../srv/base/PageCheckController.java:326` — 修复既有 bug
- `dao.save(request)` → `dao.insert(request)`。现状：312 行手工 setId(UUID) 后 save 生成影响 0 行的 UPDATE，页面接管请求从未真正插入；改后按指定 id 真实插入。

### 6. 测试：扩展 `geelato-core/src/test/java/cn/geelato/core/meta/model/parser/EntitySaveParserTest.java`
沿用现有 TestSaveEntity + StaticApplicationContext 模式，新增用例：
- 强制 Insert 且带指定 id → CommandType.Insert、valueMap 中 id 等于指定值、where 为 null、触发 Insert 型字段填充。
- 强制 Insert 且 id 为空 → 自动生成非空 id。
- 强制 Update 且 id 为空 → 抛 `IllegalArgumentException`。
- 强制 Update 且带 id → where 条件正确。
- 不传 forcedType（原 save 路径）→ 行为与现状一致（回归保障）。

### 7. 文档：新增 `docs/orm/dao-save-semantics.md`
与 docs/orm 现有文档风格一致，说明 save/insert/update 三者语义、判定链路（Dao → EntityManager → EntitySaveParser）、以及"指定 id 插入"用法示例。
