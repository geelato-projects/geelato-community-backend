# 为 mql-playground.html 增加 SQL 美化

## 目标文件
`geelato-mql-test/src/main/resources/static/mql-playground.html`（唯一源文件；`target/classes/static/` 下的是构建产物，不手动改，重新构建会自动同步）

## 现状
- 页面零外部依赖，纯自包含 HTML。
- 后端返回的 SQL 通过 `esc()`（仅 HTML 转义）直接渲染到 3 处 `<pre class="sql-block">`：第 561 行（生成 SQL）、第 577 行（Count SQL）、第 693 行（场景集结果 SQL）。
- 无任何格式化/高亮逻辑。

## 实现步骤

### 1. 本地引入 sql-formatter 库
- 新建目录 `geelato-mql-test/src/main/resources/static/lib/`。
- 下载 sql-formatter 的浏览器可用压缩版到 `static/lib/sql-formatter.min.js`。
  - 优先选用提供 UMD/IIFE 全局（暴露 `window.sqlFormatter`）的版本，便于用普通 `<script>` 同步加载。
  - 下载后**打开文件确认其暴露的全局名与 API**（`sqlFormatter.format(sql, { language, indent })` 的确切签名因大版本而异：v4/v5 为 UMD 全局；v6+ 改为 ESM）。据此决定引用方式：
    - 若是 UMD 全局：用普通 `<script src="lib/sql-formatter.min.js"></script>`。
    - 若仅 ESM：用 `<script type="module">` 把 `format` 挂到 `window.sqlFormatter` 上，供后续普通脚本调用（因格式化只在用户点击 Explain/Execute 后触发，模块加载时序无影响）。
  - 若环境无法联网下载，则退回“手写轻量格式化函数”方案（兜底，会在动手时与你确认）。

### 2. 在 `<head>` 中引入库
在 `</style>` 之后、`</head>` 之前加入（相对路径，兼容 context-path / 反代子路径）：
```html
<script src="lib/sql-formatter.min.js"></script>
```

### 3. 新增 `formatSql()` 包装函数
在 `esc()` 附近（约第 616 行）加入防御性包装：格式化失败时原样返回，绝不影响渲染；方言优先 `mysql`（与平台数据库一致），缩进 2 空格。
```js
function formatSql(sql) {
    if (!sql) return '';
    try {
        const fn = (window.sqlFormatter && (window.sqlFormatter.format || window.sqlFormatter)) || window.formatSql;
        if (typeof fn !== 'function') return sql;
        return fn.call(window.sqlFormatter, sql, { language: 'mysql', indent: '  ' });
    } catch (e) { return sql; }
}
```
> 调用顺序保证：先 `formatSql` 再 `esc`，避免重复转义或把 `&` 等字符破坏格式化。

### 4. 替换 3 处渲染点
- 第 561 行：`${esc(r.sql || '')}` → `${esc(formatSql(r.sql || ''))}`
- 第 577 行：`${esc(r.countSql)}` → `${esc(formatSql(r.countSql))}`
- 第 693 行：`${esc(r.sql)}` → `${esc(formatSql(r.sql))}`

### 5. CSS（保持现状，无需改动）
`.sql-block` 已有 `white-space: pre-wrap`，能正确保留格式化后的换行与缩进；`word-break: break-all` 保证超长行也能换行。无需修改。

## 不在本次范围

- 不改 AST 页签（JSON 已美化）。
- 不替换 MQL 编辑器为富文本编辑器。
- 不新增“复制 SQL / 原文切换”按钮（如需可后续追加）。

- 跑“测试场景集 → 全部运行”：确认每个场景详情里的 SQL 也已美化。
- 断网/库加载失败时：确认 SQL 仍以原文显示（不报错、不空白）。
