## 任务二：修复 TableView 构造函数 NumberFormatException

### 根因
- `platform_dev_view.enable_status` 列是 `tinyint(1)`；MySQL JDBC 默认 `tinyInt1isBit=true`，把 tinyint(1) 映射为 `Boolean`
- `select *` 返回的 Map 里 `enable_status = Boolean.TRUE`，`toString()` = `"true"`
- 我上个变更新写的 `TableView(Map)` 用 `Integer.parseInt("true")` → 崩溃（TableView.java:80）
- 旧代码不崩的原因：旧路径（`getViewMetas`/`getEntityMetaByView(Map)`）**从未读过 view 行的 enable_status**；我写构造函数时误参考了 `TableCheck(Map)` 的 parseInt 写法（check 表该列返回数字），但 view 表该列返回 Boolean

### 修复
`TableView.java` 新增私有静态宽容解析方法，并替换三处调用：

```java
private static int parseTinyint(Object value, int defaultValue) {
    if (value == null) return defaultValue;
    if (value instanceof Boolean) return (Boolean) value ? 1 : 0;
    String s = value.toString();
    if ("true".equalsIgnoreCase(s)) return 1;
    if ("false".equalsIgnoreCase(s)) return 0;
    try { return Integer.parseInt(s); }
    catch (NumberFormatException e) { return defaultValue; }
}
```

| 调用点 | 修改 |
|---|---|
| `enableStatus`（崩溃点，:80） | `Integer.parseInt(...)` → `parseTinyint(map.get("enable_status"), ColumnDefault.ENABLE_STATUS_VALUE)` |
| `linked`（隐患，view 行该列类型未经旧代码验证） | 同上换 `parseTinyint(map.get("linked"), 0)` |
| `del_status`（顺手加固，等价容错） | 同上换 `parseTinyint(map.get("del_status"), 0)` |

### 不动其他四个类
TableMeta/ColumnMeta/TableCheck/TableForeign 的解析规则均来自旧代码已验证的行为（table/column/check/foreign 行的数值列返回数字），保持原样避免引入新变量。
