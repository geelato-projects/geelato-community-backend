# ORM Dao 绑定优先级反转:dynamicDao 优先

## 背景与目标

框架层两个 Dao Bean 已存在,无需新增定义:
- `primaryDao`:geelato-web-platform `DataSourceConfiguration.java:34`(quickstart 实际生效)
- `dynamicDao`:geelato-orm `DynamicDaoConfiguration.java:22`(经 `OrmDynamicDataSourceAutoConfiguration` 装配)

问题:`OrmDaoResolver` 多 Dao 回退顺序是 primaryDao 优先,导致 quickstart 被迫显式配置 `geelato.orm.dao-bean-name=dynamicDao`。且绑 primaryDao 时 `useDataSource(connectId)` 完全失效(ThreadLocal key 只有 `DynamicRoutingDataSource` 消费)。

目标:**dynamicDao 存在时 ORM 必绑 dynamicDao;仅当 dynamicDao 不存在时才用 primaryDao**。quickstart 不再需要任何显式配置。

## 改动清单

### 1. OrmDaoResolver 重构(核心,geelato-orm)

`OrmDaoResolver.resolve()` 新优先级:
1. `geelato.orm.dao-bean-name` 显式配置 → 按名取(保留逃生通道,bean 不存在仍硬失败)
2. 容器含 `dynamicDao` → 绑 dynamicDao(`getBean("dynamicDao", Dao.class)`,类型不符抛错硬失败)
3. 容器含 `primaryDao` → 绑 primaryDao
4. 按类型 `getBean(Dao.class)` 唯一 → 用它(兼容自定义单 Dao 应用)
5. 多个或零个 → 硬失败,报错提示配置 `geelato.orm.dao-bean-name`

删除旧 `resolveCompatibilityDao` 的 primaryDao→dynamicDao 顺序;类注释与报错文案同步说明理由:只有走 DynamicRoutingDataSource 的 Dao 才能支撑 `useDataSource`/实体 connectId 切库。

### 2. quickstart 配置清理

删除 `geelato-web-quickstart/src/main/resources/application.properties:5` 的 `geelato.orm.dao-bean-name=dynamicDao`。

### 3. 测试更新(geelato-orm/src/test)

- `OrmAutoConfigurationTest`:
  - `shouldFallbackToPrimaryDaoForCompatibility` 改为断言多 Dao(含 dynamicDao)时**绑 dynamicDao**
  - 新增:primaryDao + dbGenerateDao、无 dynamicDao 场景 → 绑 primaryDao
  - 现有 SingleDao / 显式 dao-bean-name / 歧义报错 / 缺 Dao 报错用例保留适配
- `OrmRuntimeProviderTest`:fallback 测试的 mock ApplicationContext 补 `containsBean("dynamicDao")/("primaryDao")` stub,断言不变
- 新增一个模拟 quickstart bean 组合(primaryDao + secondaryDao + dbGenerateDao + dynamicDao)的用例,断言绑定 dynamicDao

### 4. 文档同步

- `geelato-orm/README.md`:回退顺序描述改为 dynamicDao → primaryDao → 唯一,并说明切库语义
- `docs/orm/backend-fluent-dsl-guide.md`、website official-docs 两篇中涉及 dao-bean-name 的说明同步

### 5. 不动的部分(明确说明)

- `resolveEffectiveDefaultDataSourceKey`(默认 key="primary")不动:DynamicRoutingDataSource 的兜底数据源就是 primary,语义一致
- framework-starter 与 OrmDynamicDataSourceAutoConfiguration 两条装配路径的收敛、geelato-mcp 的 primaryDao(不依赖 orm)——超出本次范围

## 验证

1. geelato-orm 全量 `mvn test`
2. 整仓 `mvn test-compile -DskipTests` 确认下游(web-platform/quickstart)无影响
3. quickstart 删配置后,由新增的 bean 组合测试证明自动绑定 dynamicDao
