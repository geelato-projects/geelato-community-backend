# /export/template/get 偶发空数据 — 最小修复（2 处改动）

## 根因回顾
运行期 `refreshDBMeta` 把类注册的 ExportTemplate 元数据（classType=ExportTemplate.class）替换为 DB 源元数据（classType=null），`CommonRowMapper.mapRow` 在 classType 为空时静默 `return null` → `ApiResult.success(null)` → success + 空数据；重启后类扫描重新注册才恢复。触发源：应用包部署 `refreshAppV2`/`refreshApp`、模型管理、`/meta/sync`。

## 改动 1：ExportTemplate 标记为平台实体（根因阻断）
`geelato-meta/src/main/java/cn/geelato/meta/ExportTemplate.java:19`

```java
@Entity(name = "platform_export_template", catalog = "platform")
```

利用既有平台保护：`refreshDBMeta` 直接拒绝（「实体标记为平台，无法刷新」），打包部署后的元数据刷新自动跳过。已核实 catalog 其余消费点（resolveConnectId 路由、冲突检测、代码生成）均无副作用。

## 改动 2：CommonRowMapper 兜底（数据不丢、不抛异常）
`geelato-core/src/main/java/cn/geelato/core/meta/model/CommonRowMapper.java`

classType 为空（DB 在线源实体无 Java 类）或元数据缺失时，不再 `return null`，改为返回 `LinkedHashMap`：
- 有 EntityMeta：按 `em.getFieldMetas()` 匹配 columnName，key 用 `fm.getFieldName()`（与 BeanUtils 属性设置同源）；未匹配到的列用 columnName 做 key
- 无 EntityMeta：全部用结果集 columnName 做 key
- String 值保持现有 `EncryptUtils.decrypt` 逻辑一致
- bean 路径反射构造失败的 catch 同样退化为 Map 兜底（消除现有静默 return null）

调用方 `ApiResult.success(...)` 直接 JSON 序列化，Map 形态对前端可读。
