# 修复 MQL 生成 SQL 的两个 Bug

## 问题确认（根因）

两个 Bug 都在 `MetaQuerySqlProvider` / `MetaBaseSqlProvider`（MQL→SQL 的唯一生成入口），已逐行核对源码确认。

### Bug 1：排序字段别名被包进反引号
- `MetaQuerySqlProvider.buildOneSql`（第 88-95 行）：先用 `resolveOrderBy()` 给列加反引号得到 `` `update_at` desc ``，**再**用 `decorateOriginalWhere()` 跑正则 `(?<!\.)\bupdate_at\b` 注入表别名。
- 因为反引号 `` ` `` 是非单词字符，`\b` 在反引号边界匹配，别名 `t0.` 被注入到反引号**内部** → `` `t0.update_at` desc ``（错误）。
- 正确应为 `t0.`update_at` desc`（反引号只包列名）。
- 仅当存在 JOIN（主表别名 `t0` 非空）时触发，所以现有不带 JOIN 的 `@order` 测试都没暴露。

### Bug 2：多个外键指向同一张表时只生成一个 JOIN
- `buildForeignJoins`（第 318-332 行）：`joinMap` 按**目标表名** `tf.getForeignTable()` 去重。两个不同外键（如 `placeOfDelivery`、`entrepot`）指向同一张目标表时，第二个被丢弃。
- `buildTableAlias`（基类第 549-554 行）：别名按**表名**分配，即使生成两个 JOIN 也会共用同一别名。
- 结果：只产生一个 JOIN（且 ON 条件用的是第一个外键的列），第二个 `ref` 字段读到的其实是第一个外键关联的数据。

## 修复方案

### 修复 1：ORDER BY 别名与反引号（Bug 1）

**文件 `geelato-core/.../sql/provider/MetaBaseSqlProvider.java`**

把现有 `resolveOrderBy(EntityMeta, String)`（第 383-402 行）改为委托给一个新的别名感知重载，在加反引号**之前**加表别名：

```java
protected String resolveOrderBy(EntityMeta em, String orderBy) {
    return resolveOrderBy(em, orderBy, null);
}

protected String resolveOrderBy(EntityMeta em, String orderBy, String alias) {
    // ... 遍历每个排序项 ...
    String columnName = resolveOrderByColumn(em, parts[0]);
    if (alias != null && !columnName.contains(".")) {
        result.append(alias).append(".");   // 先加别名
    }
    appendQuotedIdentifier(result, em, columnName);  // 再反引号包列名
    // ... 方向 asc/desc ...
}
```

**文件 `geelato-core/.../sql/provider/MetaQuerySqlProvider.java`** — `buildOneSql` 第 88-95 行改为：

```java
if (StringUtils.hasText(command.getOrderBy())) {
    sb.append(" order by ");
    sb.append(resolveOrderBy(md, command.getOrderBy(), md.getTableAlias()));
    // 删除原来的 decorateOriginalWhere(md, ob) 调用
}
```

- `MetaViewQuerySqlProvider` 仍调用无别名重载 `resolveOrderBy(md, orderBy)`（行为不变，不受影响）。
- GROUP BY 不受影响（其值是原始列名、不预先加反引号，`decorateOriginalWhere` 在那里正常工作）。

### 修复 2：每个外键独立 JOIN 与别名（Bug 2）

**文件 `geelato-core/.../sql/provider/MetaQuerySqlProvider.java`**

新增私有方法，按**外键源字段**生成唯一别名 key：

```java
private String foreignAliasKey(TableForeign tf) {
    return "fk::" + tf.getMainTableCol();
}
```

`buildForeignJoins`（第 314-350 行）两处改动：
1. 去重 key 由 `tf.getForeignTable()`（目标表）改为 `tf.getMainTableCol()`（外键源列）——不同外键即使指向同一表也各自一个 JOIN，同一外键被多个 `ref` 引用仍共用一个 JOIN。
2. 别名由 `buildTableAlias(foreignEm.getTableName())` 改为 `buildTableAlias(foreignAliasKey(tf))`。

`buildSelectFields` 外键分支（第 229 行）同步改为 `buildTableAlias(foreignAliasKey(tf))`，保证 SELECT 列与 JOIN 用同一个别名（同一 `tf` → 同一 key → 同一别名）。

> 别名分配顺序：`buildSelectFields` 先于 `buildForeignJoins` 执行并完成别名分配，`buildForeignJoins` 复用已分配的别名，二者 key 一致，不会错位。

## 回归测试（`geelato-mql-test`）

### 1. 为测试实体增加"指向同一张表的第二个外键"
**文件 `.../mqltest/testmodel/MqlTestOrder.java`** 新增字段（该实体已自动被 `MqlTestSupport.registerTestModels()` 注册，无需额外接线）：

```java
@Title(title = "审批人")
@ForeignKey(fTable = MqlTestUser.class)
@Col(name = "approver_user_id", dataType = "BIGINT")
private String approverUserId;
```
这样 `userId`、`approverUserId` 都指向 `mql_test_user`，复现 Bug 2。

### 2. 在 `SelectJoinPageSqlTest.java` 新增测试
- `JoinClause`：`twoFksSameTargetTable()` —— 断言生成**两个** `left join mql_test_user`，别名分别为 `t1`/`t2`，ON 条件分别用 `user_id`/`approver_user_id`。
- `OrderByClause`：`orderWithJoinAlias()` —— `@fs:ref(...) + @order:age|-` 组合，断言含 `t0.\`age\`` 且**不含** `` `t0.age` ``（用 `assertSqlNotContains`，需补 import）。

### 验证步骤
1. 编译：`mvn -q -pl geelato-core install -DskipTests`
2. 跑测试：`mvn -q -pl geelato-mql-test test -Dtest=SelectJoinPageSqlTest`
3. 全量回归：`mvn -q -pl geelato-mql-test test`（确认现有 SELECT/ORDER/JOIN/分页/视图测试不被破坏）

改动范围：3 个核心源文件（`MetaBaseSqlProvider`、`MetaQuerySqlProvider`）+ 1 个测试实体 + 1 个测试类，均为最小侵入式修改。
