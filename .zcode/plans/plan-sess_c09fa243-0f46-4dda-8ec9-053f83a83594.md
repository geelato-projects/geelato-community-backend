# 修复：打包部署刷新实体缓存时跳过平台实体

## 根因

部署后的批量缓存刷新循环（v1 `refreshApp`、v2 `refreshAppV2`）只按 `appId` 筛选实体，未过滤 `catalog="platform"` 的实体。platform 实体（如 `TableMeta`、`ColumnMeta`、`App`、`Dict` 等 30+ 个）被 `refreshDBMeta` 拒绝并抛 `RuntimeException`，导致循环中断、后续实体缓存全部未刷新、部署接口报错"刷新应用元数据缓存失败"。

## 修改内容（共 2 处，均在 geelato-web-platform）

### 1. `PackageController.refreshApp`（v1 引擎，PackageController.java:359-369）

循环内 appId 匹配后，先判断 `"platform".equalsIgnoreCase(entityMeta.getCatalog())`，是则计数跳过（`continue`），不调用 `refreshDBMeta`。完成日志增加跳过数量：

```java
private void refreshApp(String appId) {
    int refreshed = 0;
    int skippedPlatform = 0;
    List<EntityMeta> allEntityMeta = MetaManager.singleInstance().getAll().stream().toList();
    for (EntityMeta entityMeta : allEntityMeta) {
        if (entityMeta.getTableMeta().getAppId() != null && entityMeta.getTableMeta().getAppId().equals(appId)) {
            if ("platform".equalsIgnoreCase(entityMeta.getCatalog())) {
                skippedPlatform++;
                continue;
            }
            MetaManager.singleInstance().refreshDBMeta(entityMeta.getEntityName());
            refreshed++;
        }
    }
    log.info("刷新应用元数据缓存完成：appId={}, 刷新实体 {} 个, 跳过平台实体 {} 个", appId, refreshed, skippedPlatform);
}
```

### 2. `PackageService.refreshAppV2`（v2 引擎，PackageService.java:737-745）

同样处理；该方法原本没有任何完成日志，一并补上：

```java
private void refreshAppV2(String appId) {
    Collection<EntityMeta> allEntityMeta = metaManager.getAll();
    int refreshed = 0;
    int skippedPlatform = 0;
    for (EntityMeta entityMeta : allEntityMeta) {
        String metaAppId = entityMeta.getTableMeta().getAppId();
        if (metaAppId != null && metaAppId.equals(appId)) {
            if ("platform".equalsIgnoreCase(entityMeta.getCatalog())) {
                skippedPlatform++;
                continue;
            }
            metaManager.refreshDBMeta(entityMeta.getEntityName());
            refreshed++;
        }
    }
    log.info("刷新应用元数据缓存完成：appId={}, 刷新实体 {} 个, 跳过平台实体 {} 个", appId, refreshed, skippedPlatform);
}
```

## 不改的部分（有意保留）

- `MetaManager.refreshDBMeta`（MetaManager.java:177-185）的 platform 防护异常保留：单实体操作场景（DevTableController 等十多处调用点）仍需向用户明确报错；platform 实体元数据以 Java 类源为准，从 DB 刷新会丢失 catalog 信息，防护是必要的。
- 循环中其他刷新异常仍按现状整体抛出报错（部署数据已落库、缓存未刷新需要明确提示），不做单实体异常隔离。

## 验证

- `mvn compile -pl geelato-web-platform -am -q` 编译通过。
- 行为验证：部署 geelato_admin（含 platform 实体的应用）后不再报"实体标记为平台，无法刷新"，非 platform 实体正常刷新，日志可见"刷新实体 N 个, 跳过平台实体 M 个"。
