平台实体总览

geelato-meta 是平台业务实体的集中定义模块：平台自身运行所需的实体——应用、组织、用户、角色权限、字典、消息通知、文件附件、调度集成等——全部在该模块的 cn.geelato.meta 包下用 @Entity 注解声明，共 54 个。本章按业务域逐实体给出字段级目录；其他特性模块（业务告警、业务异常、邮件等）的实体见全平台实体索引。

模块定位​

项说明
模块坐标geelato-meta（cn.geelato.meta 包）
上游依赖geelato-utils、geelato-lang（注解）、geelato-core（实体基类与元数据模型）
下游消费方geelato-web-common、geelato-web-platform、geelato-mcp-fms、geelato-mcp-platform
注册方式零手工注册：启动时 MetaConfiguration 按 geelato.meta.scan-package-names（默认 cn.geelato）扫描 @Entity 注解类，自动注册进 MetaManager

实体元数据如何被解析、缓存与消费（ORM SQL 生成、MQL 校验、数据源路由等）属于框架元数据机制，见元数据说明；@Entity/@Col/@Title 等注解的写法见ORM 注解说明。

启用状态（enable_status）​

enable_status 不在公共基类中。实现 EntityEnableAble 接口的实体共 9 个：Role、User、Dict、DictItem、SysConfig、Qrcode、ExportTemplate、UserEmailAccount、UserDelegateMap，取值 1 启用、0 停用（默认 1）。Api、AppSqlMap、EncodingLog 有同义字段但未实现该接口。

数据落库分布（catalog）​

@Entity(catalog) 决定实体归属的库：

catalog实体说明
platform48 个平台主库，绝大多数实体
emailEncodingLog编码记录，落邮件库
platform-logPlatformExceptionLog平台错误日志，独立日志库
未标注Area、Compress、Message、Notice、Qrcode、UserStockMap按默认数据源归属规则解析，见实体绑定与优先级

约定与阅读提示​

  • 字段表"列名"默认取 @Col(name)；未标注 @Col 的字段按属性名驼峰转蛇形推导列名。
  • 字段含义以源码字段级 @Title（title + description）为准。个别实体的类级标题存在注释失真（如 Schedule 类级标题误写为"应用"、Tenant 误写为"租户站点"、UserStockMap 名含 stock 实为常用联系人），本章按实际语义撰写并就地加注。
  • *Map 后缀实体为关联表（两张表之间的映射），通常字段很少。
