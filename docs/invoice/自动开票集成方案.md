# 自动开票集成方案（v0.2 实施勘误版）

> 状态：**已实施**（模块 `geelato-invoice-integrate`，包 `cn.geelato.dyn.invoice.integrate`）；本版按真实开发库探查与实施评审对 v0.1 勘误，缺陷修正见第 13 节（F1–F7）
> 范围：一期对接**百望**自动开具数电**蓝票**；红冲（冲红）、诺诺平台为二期预留
> 关联：建表 DDL 见 [invoice-tables.sql](invoice-tables.sql)；百望接口资料在 `D:\geelato\geelato-enterprise\baiwang\`（apifox 集合、7 份官方 PDF、沙箱实测脚本与报告）

## 1. 背景与目标

**现状**：发票由外部开具后手工上传 PDF，走平台 OCR 识别接口（`geelato-web-platform .../srv/ocr/invoice`，`POST /ocr/invoice/recognize[/fileId]`），宿主应用将识别结果手工回写 `il_invoice_req_file` 等表。

**目标**：geelato-dyn 新增模块轮询业务源（一期=开票申请表 `il_invoice_req`），发现审批通过的申请后，按**开票信息所标记的集成平台**自动调百望 OpenAPI 开票；开票受理、结果跟踪、来源单据回写、发票文件归档全程异步；所有开票记录集中在开票任务表。

## 2. 决策记录

| # | 决策 | 说明 |
|---|---|---|
| D1 | 平台路由 | **勘误**：真实库 `il_info_for_invoicing` 已存在 `invoicing_platform varchar(64)`，直接复用该列，**无需加列**（v0.1 建议新增 `invoice_platform` 作废，避免双列漂移）；申请时选的开票信息决定进哪个平台开票（BW=百望、NN=诺诺预留） |
| D2 | 开票任务表来源无关 | 任务表关联字段抽象命名（biz_type/biz_id/biz_no），开票申请只是来源之一（`INVOICE_REQ`），后续其他业务表接入不改表 |
| D3 | 发票项目=申请时人工填写 | 申请人在发票主体的"发票项目明细"子表中选择基础表项目（带出编码/税率）并填含税金额；`il_invoice_req_detail` 是开票**费用**明细，与发票项目不是一一绑定关系，**不做任何改动**；明细表**对开票任务透明**——任务只读，不回写不持有 |
| D4 | 一期仅蓝票 | 表结构预留红冲（task_type、原票关联二期加列） |
| D5 | 发票文件转存平台附件 | 开票成功后下载 pdf/ofd/xml 转存平台附件并插 `il_invoice_req_file` 登记行，自动发票与手工登记发票同列表展示；转存失败不阻断成功状态，单独标记重试 |
| D6 | 一次申请可开多张发票 | 新增**发票主体表**（`il_invoice_subject`）：申请下按"张"拆分，每张有独立发票抬头（默认从申请带下、可编辑）与项目明细；主体表**只关联开票申请**（invoice_req_id，无抽象关联列）；开票任务按主体 1:1 生成，每张发票一个任务 |
| D7 | 主体承载实际发票信息 | 开票成功后由任务回填主体：发票号码/数电号码、开票时间、实际不含税与税额（服务端重算值）、PDF 转存附件；任务表保留开票过程记录；`total_amount` 保留申请口径作对账；**不设发票代码/校验码列**（数电票无此栏位） |

## 3. 发票项目标准符合性调研

对照数电发票票面要素、国标《电子发票基础信息规范》（征求意见稿）、百望/诺诺开票接口实测与文档：

| 标准要求 | 本设计 | 结论 |
|---|---|---|
| 票面明细 8 要素：项目名称、规格型号、单位、数量、单价、金额、税率/征收率、税额 | 基础表+明细表全覆盖 | 满足 |
| 票面项目名称 = `*税收分类编码简称*明细名称`，简称由税局按编码自动匹配，接口传明细名称即可 | `item_name` 只存明细名称；`goods_simple_name` 开票成功后回显存档 | 满足 |
| 19 位商品和服务税收分类编码必选；不选编码=栏目填写不全=不合规发票 | `tax_classification_code` 必填，组票校验 19 位数字，不符硬失败 | 满足 |
| 零税率行（官方 4 态：freeTaxMark 空/0-正常、1-免税、2-不征税、3-普通零税率）：税率传空 + 增值税特殊管理必填备案说明（枚举：免税/不征税/简易征收/先征后退等），否则税局校验失败 | `tax_rate` 可空 + 组合校验（free_tax_mark ∈ 1/2/3 → tax_rate 须空且 vat_special_management 必填；否则 tax_rate 必填且在档位白名单） | 满足 |
| 票种区分（普票/专票）：官方 invoiceTypeCode 枚举——01 数电专票、02 数电普票、026 电子普票（文档默认）、028 电子专票、004/007/025 纸质专票/普票/卷式、85/86 数电纸质专票/普票、87/88 机动车/二手车、005/006 同前纸质 | 任务表 `invoice_type_code`（申请 `invoice_type` 经 cfg 映射白名单转换）+ 第 7 节票种差异化校验 | 满足 |
| 特定业务标志 invoiceSpecialMark：00 普通、01 成品油、03 建筑服务、**04 货物运输服务**、05 不动产销售等 | 任务表 `invoice_special_mark`（默认'00'），与票种映射一并由 cfg 配置 | 满足 |
| 折扣行（invoiceLineNature 区分普通行/折扣行） | 明细表预留 `invoice_line_nature`，一期非 '0' 即硬失败 | 预留 |
| 差额征税（扣除额；差额票限一条商品行） | 预留 `deductible_amount`，一期非空>0 即硬失败 | 预留 |
| 数电票已废除清单开票、无 8 行限制（官方答复建议 ≤2000 行） | `invoiceListMark` 透传空，无清单逻辑 | 满足 |
| 诺诺/用友税务云明细字段与百望同构 | 基础表/明细表字段对 BW/NN 通用，channel 路由预留 | 满足 |
| 数电票票面不设收款人/复核/开票人栏次 | 不存 drawer/payee/checker | 一致 |

税率档位白名单（cfg 可配）：13%、9%、6%、5%、3%、1%、0.5%（0.13/0.09/0.06/0.05/0.03/0.01/0.005）。

## 4. 表设计

四张新表（DDL 详见 [invoice-tables.sql](invoice-tables.sql)，MySQL 8.0、与 il_ 表同库同风格：utf8mb3、平台标准审计 12 列、del 列参与唯一索引）+ 存量表加列建议。

数据层级：**开票申请 `il_invoice_req`（已有）→ 1:N 发票主体 → 1:N 发票项目明细**；开票任务与发票主体 1:1（biz 引用主体，可溯源申请）。

### 4.1 `il_invoice_item` 发票项目基础表（下拉维护源）

仅作下拉维护源：被选择时字段**全量冗余**到明细行，不构成引用关系——基础表后续修改/删除不影响已申请与已开票数据。

| 列 | 类型 | 说明 |
|---|---|---|
| item_code | varchar(64) | 项目编码，唯一（含 del 列） |
| item_name | varchar(128) | 票面明细名称（简称由税局按编码自动生成） |
| goods_simple_name | varchar(64) | 商品简称（编码带出，展示用） |
| tax_classification_code | varchar(19) | 税收分类编码，19 位数字必填 |
| tax_rate | decimal(8,6) | 税率；**可空**（免税行不填） |
| specification / unit | varchar(64)/varchar(32) | 规格型号/单位 |
| preferential_mark / free_tax_mark | varchar(2) 默认'0' | 优惠政策/免税标志 |
| vat_special_management | varchar(128) | 增值税特殊管理（免税时必填） |
| deductible_amount | decimal(18,2) | 差额征税扣除额（预留） |
| remark / seq_no / enable_status | | 备注 / 排序 / 启用状态 |

### 4.2 `il_invoice_subject` 发票主体表（一张发票的载体：申请时录入，开票后回填实际发票信息）

申请下按"张"拆分：每张独立发票抬头（默认从申请购方信息带下、可编辑）；**只关联开票申请（invoice_req_id），不做其他关联**；开票成功后由任务**回填实际发票信息**（发票号码/开票时间/服务端实际金额/发票附件）——主体是发票信息的落身之处，任务表保留开票过程记录（受理/轮询/报文快照）。

| 列 | 类型 | 说明 |
|---|---|---|
| invoice_req_id | varchar(32) | 所属开票申请（il_invoice_req.id），索引，唯一关联 |
| subject_no | varchar(64) | 主体编号，申请内唯一（建议 申请号-张号，如 REQ202611180001-01） |
| seq_no | bigint | 排序号（张次顺序） |
| 抬头（购方） | | buyer_name（必填）、buyer_tax_no、buyer_address、buyer_bank、buyer_bank_account、natural_mark（默认从申请带下，可编辑）；**不含邮箱与电话**——交付邮箱用申请 buyer_email，电话组票时取申请 buy_tel |
| invoice_type | varchar(1024) | 发票类型（默认从申请带下，可编辑；组票经 cfg 映射白名单转 invoiceTypeCode） |
| remarks | varchar(512) | 票面备注（该张） |
| total_amount | decimal(18,2) | 该张价税合计（=项目明细合计；各主体合计之和须=申请 total_expenses） |
| **开票结果回填** | | invoice_no（20 位数电号码）、digit_invoice_no（与号码一致，红冲/交付键）、invoice_time、total_price/total_tax（服务端实际值，total_amount 保留申请口径作对账）、file_id（PDF 转存附件）；**不设发票代码/校验码列**——均为纸票时代栏位，数电票没有，将来开纸票再 ALTER 加列 |

### 4.3 `il_invoice_item_detail` 发票项目明细表（主体的项目行，组票输入）

**挂发票主体**（`invoice_subject_id`，一张发票多个项目）；**不引用基础表**：选择基础表项目时字段全量冗余进本表（item_code 即业务追溯键）；对开票任务**透明**：任务只读，行级服务端回算值保留在任务表 `request_payload`/`last_response` 报文快照中。

| 列 | 类型 | 说明 |
|---|---|---|
| invoice_subject_id | varchar(32) | 所属发票主体（一张发票），索引 |
| line_no | int | 行号 |
| 项目字段（选择时全量冗余） | | item_code、goods_name、goods_simple_name、tax_classification_code、tax_rate、specification、unit、preferential_mark、free_tax_mark、vat_special_management、deductible_amount、invoice_line_nature(默认'0') |
| quantity / price | decimal(18,6) 可空 | 空=按 1×amount 组票（priceTaxMark=1 含税） |
| amount | decimal(18,2) | 项目含税金额（人工填写；校验 >0、合计=来源申请金额） |
| remark | varchar(256) | |

### 4.4 `il_invoice_task` 开票任务表（来源无关、渠道无关的开票记录总表；与发票主体 1:1）

| 分组 | 字段 |
|---|---|
| 业务来源（抽象） | biz_type（一期 'INVOICE_SUBJECT'=发票主体，可溯源申请）、biz_id（联合索引）、biz_no（冗余展示，建议 申请号+张号） |
| 任务自身 | task_no（唯一）、task_type('1'蓝票/'2'红冲预留)、channel（=开票信息 invoicing_platform，如 'BW'） |
| 销方/开票信息快照 | seller_invoicing_id（索引）、seller_name、seller_tax_no、seller_address、seller_tel、seller_bank、seller_bank_account（**勘误：一律取申请行 seller/seller_tax_id/seller_address/seller_tel/seller_bank/seller_bank_account**；开票信息表仅用于平台路由与按 seller_invoicing_id 定位百望账号，不提供票面数据） |
| 购方快照 | buyer_name、buyer_tax_no、buyer_address、buyer_bank、buyer_bank_account、natural_mark('0'/'1'自然人)（取自主体行）；buyer_email、buyer_tel（取自申请：交付邮箱、票面电话） |
| 票面控制 | invoice_type_code（票种编码：01 数电专票、02 数电普票、026 电子普票等，由申请 invoice_type 经 cfg 映射白名单转换）、invoice_special_mark（特定业务标志，默认'00'，货物运输服务为'04'）、remarks、price_tax_mark（默认'1'含税） |
| 平台往来 | order_no（唯一，幂等键，="BW"+task_no）、serial_no（索引）、request_payload/last_response（mediumtext 报文快照）、submit_at、finish_at |
| 金额 | total_price、total_tax、total_price_tax（提交前=主体 total_amount，成功后存服务端重算值）、**currency（F1 修正新增：币种快照，默认 'CNY'，百望数电票仅人民币）** |
| 结果 | invoice_no（20 位数电号码）、digit_invoice_no（数电票下与 invoice_no 恒等；两列均保留，与平台响应字段一一对应，落库直接映射）、invoice_time、pdf_url、ofd_url、xml_url、deliver_short_url |
| 归档 | file_id_pdf、file_id_ofd、file_id_xml、file_sync_status（0待/1成/2败重试） |
| 运维 | retry_count、error_code、error_message、last_poll_at、poll_count |

### 4.5 存量变动

- `il_info_for_invoicing`：**勘误——复用存量 `invoicing_platform varchar(64)` 列，无需 ALTER**（v0.1 加 `invoice_platform` 建议作废）
- `il_invoice_req`：不加列；每张（主体）开票成功后逐张回写——`invoiced_amount` 累加该张金额（**申请口径 subject.total_amount，非平台重算值，F4**）、`invoice_no` 以"、"追加该张号码（与该列"多个发票号用'、'分开"的手工登记格式一致；**F6：追加前长度校验，超 256 显式失败不截断**）、`invoice_date`（该表 `invoice_no` 列注释明确要求系统自动开票时同步结果）；`biz_status` 联动回写受 cfg 开关 `req.bizStatusWritebackEnabled` 控制**默认关**（业务语义未确认不猜测）
- `il_invoice_req_detail`：不改结构；申请下**全部主体**任务成功后，费用行 `invoice_status` 置已开票
- `il_invoice_req_file`：每张开票成功后插入登记行（file_id=转存 PDF、invoice_no、invoice_date、invoice_amount=该张价税合计；**F1：currency='CNY'、foreign_amount=0、exchange_rate=1、file_level 留空与手工登记一致；F5：插前按 invoice_req_id+invoice_no 查重幂等**）

## 5. 开票任务状态机

| 状态 | 含义 | 迁移 |
|---|---|---|
| 00 | 待提交 | 组票通过落库后瞬间态，提交成功即转 01 |
| 01 | 开票中 | 平台已受理（有 serialNo，平台 status=00），PollJob 轮询 |
| 02 | 开票成功（终态） | 平台 status=01；触发来源回写 + 文件归档 |
| 03 | 开票失败（终态） | 平台 status=02 或提交异常（网络类客户端内重试 2 次后） |
| 04 | 组票校验失败（终态，未提交） | 校验硬失败，带明确 error_message |
| 06 | 已冲红（二期预留） | |
| 07 | 已关闭（终态） | 人工处理 03/04 后关闭以解除对来源单据的占用，允许重新扫描 |

**幂等/占用规则**（主体维度）：发票主体存在 task_status ∈ {00,01,02,03,04} 的任务（biz_type='INVOICE_SUBJECT'+biz_id=主体id）即不再为该主体创建新任务；07 不占用；同一申请的多主体互不影响、各自成任务。order_no 唯一索引兜底防重复提交。

## 7. 端到端流程

1. **ScanJob**（经 InvoiceSourceConnector，一期只挂 InvoiceReqSourceConnector）：
   - 候选 SQL 语义（申请级）：`wf_approval_status='2' AND del_status=0 AND invoiced_amount<total_expenses AND 开票信息.invoicing_platform IN (scan.channels) AND 申请下存在未被占用的发票主体`（占用=该主体已有 task_status ∈ {00,01,02,03,04} 的任务，biz_type='INVOICE_SUBJECT'+biz_id=主体id；07 不占用；实现用 EXISTS 双层子查询）
   - 逐申请处理（线程池分批，shipping 模式）：读 `il_info_for_invoicing`（**仅定 channel 与账号，不取票面数据**）+ 申请下的发票主体与各主体项目明细；**对每个未占用主体独立组票，各生成一个任务（每张发票一任务）**；**F3：组票落任务在事务内先 `SELECT ... FROM il_invoice_subject WHERE id=? FOR UPDATE` 再查占用再 INSERT（主体行锁串行化竞态）**；**F2：主体存在带 serialNo 的历史 03/07 任务时，重开前强制按原 serialNo 复核平台终态（见第 13 节）**
   - **申请级校验（不符 → 该申请本轮跳过，日志 WARN + 健康上报暴露，不自动造主体）**：申请下无发票主体 / 各主体 total_amount 之和≠申请 total_expenses / 币种非 CNY（原因含币种值，F1）/ **申请金额精度超 2 位小数（F4）** / 销方税号缺失（查申请 seller_tax_id）。**勘误：账号未配置不属申请级跳过——落任务 04 硬失败**（配置缺失不会自愈，永久跳过等于静默，解决 v0.1 §6 与 §7 表述冲突）
   - **主体级组票校验（任一不符 → 该主体任务落库 04 + error_message 注明张号，不静默跳过）**：主体无项目明细 / 明细合计≠主体 total_amount / 行金额≤0 / 编码非 19 位数字 / 零税率组合不符（free_tax_mark ∈ 1/2/3 时 tax_rate 须空且 vat_special_management 必填；否则 tax_rate 必填且在档位白名单）/ **票种差异化不符**（专票系 invoiceTypeCode 01/85/004/028：buyer_tax_no 必填、natural_mark 须为空——官方标注 naturalMark 仅普票可用、明细不得含零税率行即免税不得开专票；普票系仅 buyer_name 必填即可。接口层 buyerTaxNo 非必填，合规须应用层把关）/ invoice_line_nature≠'0'（折扣行一期不支持）/ deductible_amount>0（差额征税一期不支持）/ 主体 invoice_type 不在映射白名单
   - 通过 → 每主体 INSERT task(00，biz=主体，channel=开票信息平台；抬头快照取自主体行、**销方六列快照与交付邮箱/电话一律取自申请行（勘误）**、currency 快照（F1），request_payload 固化含明细行的完整报文) → 调 issue（orderNo="BW"+task_no；goodsName 传明细名称、零税率行税率传空、金额行税额传空由服务端重算、pushEmail 取申请 buyer_email）→ 有 serialNo：task→01；提交异常：task→03
2. **PollJob**：批量取 01（serialNos≤100/批，**响应顺序不保证，按 serialNo 映射回写**）+ file_sync_status 待重试的 02：
   - 平台 00 → poll_count++/last_poll_at（**F7：超 cfg pollAlertHours（默认 24h）仍保持 01 继续轮询，健康 DOWN+WARN 显式暴露供人工介入，不自动转 03 避免诱发重复开票**）；01 → task→02 + 号码/金额/URL/invoice_time（**F4：平台重算价税合计≠申请口径 → 仍 02（票已开出不可撤）+ WARN + 健康 DEGRADED，两口径值均落库可对账**）+ **回写主体**（invoice_no/digit_invoice_no/invoice_time/total_price/total_tax）+ 经 Connector 回写来源（申请：invoiced_amount 累加该张、invoice_no 以"、"追加该张号码（F6 超长显式失败）、invoice_date；申请下全部主体任务成功时置费用明细 invoice_status=已开票）+ 下载三件文件（URL 为空显式跳过该格式，沙箱 ofd/xml 恒空）转存平台附件 → 任务 file_id_* 回写 + 主体 file_id 回填 + 插 il_invoice_req_file 登记行（F5 查重幂等）；02 → task→03 + error_code/message；**平台 03/04（纸票作废遗留态）/未知状态 → 显式暴露不改状态（数电票不应出现）**
   - 转存失败不阻断 02，置 file_sync_status=2 由 PollJob 重试
3. 异步性：扫描/提交（线程池）、结果（轮询）解耦；`scheduler.concurrent=false` 防 Job 重入。

## 13. 实施勘误与缺陷修正（F1–F7）

v0.1 方案评审发现以下设计缺陷，已按修正口径实施并在代码/单测/IT 中锁定：

| # | 缺陷 | 修正决策 | 落地位置 |
|---|---|---|---|
| F1 | **币种概念缺失**：任务/主体无 currency，非 CNY 仅扫描时隐式跳过，事后审计无据；登记行币种字段填法未定义 | `il_invoice_task` 增 `currency varchar(64) NOT NULL DEFAULT 'CNY'`（组票快照，init.sql 与 invoice-tables.sql 同步）；非 CNY 申请级跳过且健康清单原因含币种值；登记行 currency='CNY'、foreign_amount=0、exchange_rate=1 | DDL、InvoiceReqSourceConnector、InvoiceFileArchiver |
| F2 | **07 重开重复开票漏洞**：人工置 07 后新任务新 orderNo，唯一索引拦不住；原 03 可能平台侧已开出（查询误判） | 重开前强制复核：主体存在带 serialNo 的历史 03/07 任务时先按原 serialNo 查平台终态——平台 02（失败）才关闭原任务允许新建；平台 01/00 → **绝不重开**，恢复原任务为 01 交由轮询完成回写；查询异常/遗留态 → 本轮跳过 + WARN + 健康暴露，不猜测 | InvoiceIssueService（reopen 复核分支）、单测四分支 |
| F3 | **占用判定 SELECT-then-INSERT 竞态**：concurrent=false 仅防单实例重入，无任务级锁 | 组票落任务事务内先 `SELECT ... FROM il_invoice_subject WHERE id=? FOR UPDATE` 再查占用再 INSERT（主体行锁串行化）；order_no 唯一索引仍作兜底 | InvoiceIssueService.processSubject |
| F4 | **金额精度/重算差异无口径**：total_expenses decimal(18,6) vs 主体(18,2)；平台重算 ±0.01 未定义处理 | 申请金额精度超 2 位小数 → 申请级跳过显式暴露；成功后平台重算价税合计≠申请口径 → 仍 02（票已开出不可撤）+ WARN + 健康 DEGRADED，两口径值均落库（task 存平台重算值、subject.total_amount/invoiced_amount 保留申请口径）可对账 | InvoiceComposeValidator、InvoiceResultService、InvoiceReqSourceConnector |
| F5 | **归档重试不幂等**：部分成功后重试重复插登记行 | 插 `il_invoice_req_file` 前按 invoice_req_id+invoice_no 查重复用；task.file_id_* 已非空的格式不重复上传 | InvoiceFileArchiver |
| F6 | **申请 invoice_no 追加溢出**：varchar(256) 约 12 张即满 | 追加前长度校验，超长 → 该张回写显式失败（任务仍 02，error_message 记超长 + 健康暴露），**不静默截断** | InvoiceReqSourceConnector.appendInvoiceNo |
| F7 | **轮询无超时治理**：01 永久滞留无暴露 | cfg `pollAlertHours`（默认 24）：超限任务保持 01 继续轮询（不自动转 03，避免诱发 F2 重复开票），健康 DOWN + WARN 显式暴露供人工介入 | InvoiceResultService.checkPollTimeout |

其他实施勘误（正文已同步）：模块名 `geelato-invoice-integrate`（v0.1 暂定名作废）；复用存量 `invoicing_platform` 列不加列；销方快照一律取申请行六列（开票信息表仅路由+定账号）；账号未配置落任务 04 硬失败（非申请级跳过）；biz_status 回写开关默认关；归档失败显式 file_sync_status=2 重试不降级存 URL。
