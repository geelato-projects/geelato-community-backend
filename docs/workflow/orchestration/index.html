流程编排

本页说明 geelato-workflow 流程设计的核心模型：流程节点、迁移线、参与者、流程属性与流程节点属性。设计器产出 JSON 格式的流程定义，保存时由工作流服务转换为标准 BPMN 2.0 并部署到引擎；集成方只需关注本页描述的业务模型与字段，无需接触 BPMN 细节。

定义的保存、发布、版本管理等接口见流程定义集成；流程运转行为见流程运转。

定义整体结构​

一个流程定义由三部分组成：

组成说明
流程节点（workflowNodes）节点列表，必须包含启动节点与结束节点
迁移线（sequenceFlows）节点之间的连线，至少一条，决定流程走向
流程属性定义标识、名称、分组、表单页、版本状态等定义级信息
{
  "defineKey": "leave_apply",
  "name": "请假申请",
  "appId": "1001",
  "defineGroup": "人事流程",
  "pageId": "leave_form_page",
  "workflowNodes": [
    { "id": "start_1", "name": "启动", "nodeType": "start", "properties": [] },
    { "id": "initiate_1", "name": "申请", "nodeType": "initiate", "properties": [] },
    { "id": "audit_1", "name": "主管审批", "nodeType": "audit", "properties": [
        { "name": "assignee", "value": [{ "assignType": "role", "assignObject": "dept_manager" }] },
        { "name": "auditType", "value": "any" }
      ] },
    { "id": "end_1", "name": "结束", "nodeType": "end", "properties": [] }
  ],
  "sequenceFlows": [
    { "id": "flow_1", "sourceRef": "start_1", "targetRef": "initiate_1", "isAgree": 1 },
    { "id": "flow_2", "name": "同意", "sourceRef": "initiate_1", "targetRef": "audit_1", "isAgree": 1 },
    { "id": "flow_3", "name": "通过", "sourceRef": "audit_1", "targetRef": "end_1", "isAgree": 1 }
  ]
}

流程节点​

节点是流程中的处理环节，每个节点包含以下字段：

字段类型说明
idstring节点标识，定义内全局唯一，迁移线通过它引用节点
namestring节点名称（2-50 字符）
nodeTypestring节点类型，见下表
propertiesarray节点属性列表（{name, value} 对），见流程节点属性
x / y / width / heightnumber画布布局信息（设计器持久化用，可为空）

节点类型​

类型标识名称行为说明
start启动节点虚拟节点，流程入口，每个定义必须有且仅有一个
end结束节点虚拟节点，流程出口，走到该节点流程正常结束
initiate发起节点流程发起后首先到达的节点，自动绑定发起人为处理人，产生拟稿待办
audit审批节点审批人给出同意/不同意结论的节点，按并行多实例执行，多个审批人按完成规则判定
handle办理节点承办类用户任务，配置了处理人时按运行时求解结果分配；未配置时由有权限的用户自行办理
notice通知节点自动执行：按节点配置的接收人发送通知后自动向下流转，不产生待办
service自动执行节点自动执行脚本或 HTTP 调用后向下流转，不产生待办
exclusiveGateway排他网关按迁移线条件评估结果选择一条出线
parallelGateway并行网关分叉时多条出线同时到达，汇聚时等所有分支到达后放行
hq会签节点多人并行投票的审批节点，按完成规则与拒绝策略判定节点结论
countersignStart / countersignEnd会签开始/结束（存量兼容）旧版会签模型，仅存量定义兼容保留，新建流程使用 hq

:::note 自动类节点的失败兜底 通知节点与自动执行节点执行失败时，引擎自动生成一条人工兜底待办（处理人为发起人），处理人可选择重新执行（回边重跑失败节点）或跳过继续（跳过失败节点流向原下游）。 :::

迁移线​

迁移线连接两个节点，决定流程的流转路径：

字段类型说明
idstring迁移线标识
namestring迁移线名称（如"同意"/"不同意"，展示于下一步选择与流转路径文案）
sourceRefstring来源节点 id
targetRefstring目标节点 id
conditionExpressionstring条件表达式，基于表单数据/流程变量评估；排他网关出线必须配置条件
isAgreeint是否为同意类型迁移线：1 同意线、0 不同意线

迁移线的路由规则：

  • 同意线/不同意线：审批、会签节点提交时按本次结论（isAgree）筛选出线，同意走 isAgree=1 的线，不同意走 isAgree=0 的线。
  • 条件线：conditionExpression 基于流程变量（含表单数据）评估，典型用法是排他网关的多条出线按业务数据择一。
  • 默认流转：无条件或条件为真的迁移线参与路由；排他网关所有条件都不满足时流程报错，编排时应保证条件完备。
  • 并行流转：并行网关分叉后的多条出线同时生效；汇聚时等待全部分支到达。

参与者​

审批、办理、会签等用户任务节点通过 assignee 属性配置参与者，支持多条配置叠加。

处理人配置​

字段说明
assignType处理人类型：user 指定用户、role 指定角色、dept 指定部门、dept_role 部门角色（格式 orgId:roleId）、initiator 发起人
assignObject处理人标识，多个值用 , 分隔（如多个用户 id 或多个角色 id）
withChild是否包含子部门，仅 assignType=dept 时生效

各类型的运行期语义：

assignTypeassignObject 含义解析结果
user用户 id 列表直接取指定用户
role角色 id 列表该角色下全部用户
dept部门 id 列表部门下全部用户；withChild=true 时含子部门用户
dept_role部门id:角色id 列表该部门下拥有该角色的用户
initiator无需配置流程发起人（自动类节点失败兜底处理人、通知接收人使用）

参与者求解时机​

  • 提交时选人：提交任务前通过下一步与参与者求解接口获取候选处理人（StepUser），由提交人确认后随提交参数传入；目标节点是否必须选人由 needAssignee 标记决定。
  • 兜底解析：提交时对未显式选人的审批/会签节点，引擎按节点 assignee 配置自动解析参与者；解析结果为空时按节点 emptyAssigneeStrategy 处理（见下文空参与者策略）。

人数限制​

assigneeLimit 限制节点参与人数：0 表示无限制，正整数 N 表示最多选择 N 人。求解出的候选人数超过上限时，提交前须由提交人裁剪。

空参与者策略​

emptyAssigneeStrategy 决定目标节点解析不到任何参与者时的行为：

取值行为
initiator默认值。以流程发起人作为该节点处理人，避免流程卡死
skip以空参与者集合到达该节点，节点直接完成并向下流转
error提交失败并报错，提示节点未配置审批人

流程属性​

流程属性是定义级信息，随定义 JSON 一并保存：

字段必填说明
defineKey更新时必填定义唯一标识（首次创建留空由系统生成），同一 key 下按版本演进
name是流程名称
remark否备注
appId是所属应用 id，用于按应用过滤定义与任务
defineGroup否流程分组（列表页分组筛选）
pageId否关联表单页面 id，发起/办理页据此加载业务表单（iframe）
source否设计器布局原始数据（前端维护）
lockVersion否乐观锁基线，保存时校验定义是否已被他人修改

版本与状态​

同一 defineKey 下的定义按版本演进，版本状态：

状态说明
design草稿：可编辑，尚未部署到引擎
debug调试：调试发布产生，仅调试发起可运行，供发布前验证
activated当前版本：已发布，startWorkflow 等正式发起接口按此版本运行
history历史版本：被新发布版本替代，仅运行中的存量实例继续按原版本执行

发布动作（草稿发布、调试发布、批量部署）与编辑锁的接口说明见流程定义集成。

流程节点属性​

节点属性以 {name, value} 对挂载在节点的 properties 数组中，按 name 区分。全集如下：

基础属性​

属性 name适用节点value 结构与取值默认
auditTypeaudit / hqany 任意一人通过即通过；all 全部通过才通过。deptStep 部门逐级、roleStep 角色逐级为预留值，当前版本部署校验直接拒绝all
assigneeaudit / handle / hq / notice处理人配置数组，结构见参与者未配置时 handle 节点由有权限用户自行办理
assigneeLimitaudit / handle / hq0 无限制；正整数 N 限制 N 人0
page全部用户任务节点节点级表单页面 id，覆盖定义级 pageId取定义级 pageId
batchSubmitaudit / handle批量提交配置（多任务合并处理）—

表单交互属性​

属性 name适用节点value 结构与取值默认
button全部用户任务节点{按钮标识: {enabled, text, save}}。enabled 0 隐藏/1 展示；text 按钮文案；save 表单保存策略 0 不保存/1 保存/2 提示确认见按钮清单
opinionaudit / handle / hq{enabled, required, signature}：意见框显隐、必填、手写签名开关，均 0/1enabled=1，其余 0
attachment全部用户任务节点{upload, type, download, delete}：上传权限 0/1、允许类型（逗号分隔）、下载权限 0/1、删除权限 0 禁止/1 删本人/2 删所有—
ccEnabledaudit / handle / hq抄送开关 0/10
ccAssigneeccEnabled=1 时抄送人配置数组，结构与处理人配置相同—

会签规则属性（audit / hq）​

会签节点按并行多实例执行，多人同时持有待办，节点结论由完成规则与拒绝策略判定：

属性 namevalue 取值默认
completionRuleall 全部同意；any 任一同意；ratio 按比例（配合 completionValue 为百分比分子，正整数）；count 按票数（配合 completionValue 为票数阈值，正整数）all
completionValueratio 的分子（如 60 表示 60%）或 count 的票数阈值—
rejectStrategyveto_any 一票否决即回退；vote_all 全部投完再按结论判定veto_any
emptyAssigneeStrategyinitiator / skip / error，见空参与者策略initiator

:::note 审批方式与会签完成规则的关系 auditType=any/all 是审批方式的简化表达，内部映射为完成规则 any/all；completionRule 显式配置时优先于 auditType。需要比例、票数等精细控制时使用 completionRule + completionValue。 :::

分组会签属性（hq）​

分组会签将参与者划分为多个小组，每个小组作为一个意见主体参与会签：

属性 namevalue 取值默认
groupSourcedept 按部门分组（含子部门）；role 按角色分组；custom 自定义分组（配合 groups）；空 = 不分组，按普通会签处理空
groupInnerRuleall 组内全部同意该组才算同意；any 组内任一人同意即该组同意all
countingUnitmember 按人计数；group 按组计数（完成规则以组结论为计数单位）member
groupKeyName组名展示模板（如 {dept}会签）—
groupsgroupSource=custom 时的显式分组：[{key, name, members: [用户id]}]—

组内无人的分组自动跳过（标记 skipped）并从组间计数中剔除；全部分组为空时回落到 emptyAssigneeStrategy 处理。会签进度（含分组进度）通过实例详情与会签进度接口查询，结构见流程运行集成。

自动类节点属性（notice / service）​

属性 name说明
noticeConfig节点通知配置：通知模板、接收人等；引擎在节点到达/完成时发送通知
async自动节点是否异步执行：true 异步（需启用异步执行器）；默认同步执行

按钮清单​

GET /api/define/getButtonMeta 返回系统支持的按钮元数据，设计器据此渲染可配置按钮，运行时按节点类型过滤。提交按钮不参与节点配置（由运行态按节点是否需要审批结论自动注入）。

按钮标识文案默认保存表单默认展示的节点类型层级
wf_btn_agree同意保存audit / hqprimary
wf_btn_deny不同意不保存audit / hqprimary
wf_btn_back_previous退回上一步不保存audit / handlesecondary
wf_btn_back_origin退回发起人不保存audit / handlesecondary
wf_btn_back_any退回任意节点不保存audit / handlesecondary
wf_btn_stage暂存保存initiate / audit / handle / hqspecial
wf_btn_addsign加签不保存audit / hqsecondary
wf_btn_end结束流程不保存initiatesecondary
wf_btn_delete删除流程不保存initiatesecondary
wf_btn_print打印不保存全部用户任务节点special
wf_btn_circulate传阅不保存audit / handle / hq / notice / endspecial
wf_btn_attach附件上传不保存全部用户任务节点secondary

层级说明：primary 一级按钮（操作区主操作）、special 特殊按钮（表单/流程信息区右上角）、secondary 二级按钮（更多操作）。

:::note 撤回与催办 撤回、催办是页面级按钮，不纳入节点按钮配置：由详情页按当前用户与实例的关系（是否发起人、是否有待办）自动显隐。 :::

退回类按钮（退回上一步/退回发起人/退回任意节点）不开放给会签节点——会签节点只能向下流转，不支持退回。
