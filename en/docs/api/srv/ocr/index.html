OCR (ocr)

6 controllers, 24 endpoints in total. Endpoints marked with ⚙ are design-time APIs.

OCRController — /ocr​

Template supporting APIs for PDF recognition: parse PDF annotation meta, resolve or clear PDF content by template, rule testing, and time format validation.

meta Parse annotation meta​

ItemContent
URLGET /api/ocr/pdf/meta/{fileId}
ParamsfileId: path, string, attachment ID of the PDF file.
ReturnsApiResult<List<PDFAnnotationMeta>>: data is the annotation meta list resolved from the PDF (via the OCR plugin).

meta Simple template resolve​

ItemContent
URLGET /api/ocr/pdf/resolve0
ParamsfileId: query, string, attachment ID of the PDF file.
templateId: query, string, OCR PDF template ID.
wholeContent: query, boolean, optional, default false, whether to return the whole resolved PDF content.
ReturnsWith wholeContent=true, data is a PDFResolveData (whole PDF content resolved by the template meta); otherwise a List<PDFAnnotationPickContent> (contents picked at annotation positions). Fails when the file does not exist or the template/template meta is empty.

meta Clear PDF region content​

ItemContent
URLPOST /api/ocr/pdf/content/clear
ParamsfileId: query, string, attachment ID of the PDF file.
annotationPositionMetaList: body, List<AnnotationPositionMeta>, annotation position regions whose content should be cleared.
ReturnsApiResult<String>: data is the new attachment ID of the saved PDF with cleared content (genre clearPdf).

metaResolve Resolve PDF by template​

ItemContent
URLGET /api/ocr/pdf/resolve
ParamsfileId: query, string, attachment ID of the PDF file.
templateId: query, string, OCR PDF template ID; supports multiple comma-separated IDs, tried one by one.
wholeContent: query, boolean, optional, default false, whether to return the whole resolved PDF content.
ReturnsOn a template match, with wholeContent=true returns ApiResult<OcrPdfWhole> (with formatted contents), otherwise ApiResult<List<OcrPdfContent>> (formatted field contents); fails with Template matching failure when no template matches. Candidate templates must first pass the whole-content regexp validation.

ruleTest Test template rules​

ItemContent
URLPOST /api/ocr/pdf/meta/test
Paramsdata: body, Map<String,Object>, keys: content (content string to process), rule (rule JSON array string, parsed into List<OcrPdfMetaRule>), metas (meta JSON array string, parsed into List<OcrPdfContent>).
ReturnsApiResult<String>: data is the content string processed by the rules.

analysis Analyze template PDF​

ItemContent
URLPOST /api/ocr/pdf/analysis
Paramsform: body, OcrPdf entity; template is required and holds the PDF file content as Base64.
ReturnsApiResult<List<PDFAnnotationMeta>>: data is the annotation meta list resolved from the PDF. Fails when template is blank.

validateTime Validate time format​

ItemContent
URLGET /api/ocr/time/validate
Paramsformat: query, string, required, time format (DateTimeFormatter pattern).
timeZone: query, string, conditionally required when format contains a time zone marker; when given, the current time is taken in that zone.
locale: query, string, optional, locale; defaults to the system locale.
ReturnsApiResult<String>: data is the current time rendered with the given format.

AdvanceOCRController — /ocr/advance​

Advanced OCR: upload a PDF and submit a MinerU extraction task, supporting natural and AI extraction modes (synchronous, polls up to ~120 seconds).

resolve Advanced OCR resolve​

ItemContent
URLPOST /api/ocr/advance/resolve
Paramsfile: form-data file field file, required, the PDF file.
config: form-data field config, optional, JSON string: extractType (natural / ai, default natural), prompt (extraction instruction for AI mode, default 「请按照我的描述提取需要的内容」).
ReturnsApiResult<?>: in natural mode data is the resolved content list JSON (the content_list_v2.json inside the MinerU result package); in ai mode data is the JSON text extracted by DeepSeek from the resolved full.md according to prompt. Fails on task submission errors, task failure, or polling timeout (~120 seconds).

OcrPdfController — /ocr/pdf​

CRUD and select options for OCR PDF templates; a template can be maintained together with its child meta records.

pageQuery Paged query​

ItemContent
URLPOST /api/ocr/pdf/pageQuery
ParamsPagination and filter params: see Conventions
ReturnsApiPagedResult: data is a page of OCR PDF templates (OcrPdf).

query List query​

ItemContent
URLGET /api/ocr/pdf/query
ParamsPagination and filter params: see Conventions
ReturnsApiResult<List<OcrPdf>>: list of templates.

get Get details​

ItemContent
URLGET /api/ocr/pdf/get/{id}
Paramsid: path, string, template ID.
hasMeta: query, boolean, optional, true to include the child meta records.
ReturnsApiResult<OcrPdf>: template details; metas is an empty list unless hasMeta is true.

createOrUpdate Create or update​

ItemContent
URLPOST /api/ocr/pdf/createOrUpdate
Paramsform: body, OcrPdf entity; non-empty id updates, empty id creates.
hasMeta: query, boolean, optional, true to save/update the child meta records in form.metas as well.
ReturnsApiResult<OcrPdf>: the saved template.

isDelete Delete template​

ItemContent
URLDELETE /api/ocr/pdf/isDelete/{id}
Paramsid: path, string, template ID.
ReturnsApiResult<NullResult>: data is empty; soft delete (enable status set to disabled). Fails if the template does not exist.

querySelectOptions Template select options​

ItemContent
URLGET /api/ocr/pdf/select/group
ParamsNone
ReturnsApiResult<List<SelectOptionGroup>>: select options grouped by template (title); options are the meta records with configured rules under each template (name, value is the meta ID); data is empty when there is no data.

OcrPdfMetaController — /ocr/pdf/meta​

CRUD and batch rule updates for OCR PDF template meta records.

pageQuery Paged query​

ItemContent
URLPOST /api/ocr/pdf/meta/pageQuery
ParamsPagination and filter params: see Conventions
ReturnsApiPagedResult: data is a page of template meta records (OcrPdfMeta).

query List query​

ItemContent
URLGET /api/ocr/pdf/meta/query
ParamsPagination and filter params: see Conventions
ReturnsApiResult<List<OcrPdfMeta>>: list of meta records.

get Get details​

ItemContent
URLGET /api/ocr/pdf/meta/get/{id}
Paramsid: path, string, meta record ID.
ReturnsApiResult<OcrPdfMeta>: meta record details.

createOrUpdate Create or update​

ItemContent
URLPOST /api/ocr/pdf/meta/createOrUpdate
Paramsform: body, OcrPdfMeta entity; non-empty id updates, empty id creates.
ReturnsApiResult<OcrPdfMeta>: the saved meta record.

isDelete Delete meta​

ItemContent
URLDELETE /api/ocr/pdf/meta/isDelete/{id}
Paramsid: path, string, meta record ID.
ReturnsApiResult<NullResult>: data is empty; soft delete. Fails if the meta record does not exist.

updateMetaRules Batch update meta rules​

ItemContent
URLPOST /api/ocr/pdf/meta/rule/{pdfId}
ParamspdfId: path, string, template ID.
params: body, Map<String,OcrPdfMeta>, keyed by meta name, values provide the rule, discernRule, floatAreaY, and lineHeight to update.
ReturnsApiResult<NullResult>: data is empty; only updates the rule fields of existing meta records with matching names under the template, no insert or delete.

InvoiceOcrController — /ocr/invoice​

Invoice OCR recognition aligned with GB/T 42965.1-2023: PDFs go through text-layer extraction, images through RapidOCR4j; item lists (detail lines) are parsed only when requested.

recognize Recognize invoice file​

ItemContent
URLPOST /api/ocr/invoice/recognize
Paramsfile: form-data file field file, required, the invoice file (pdf/jpg/png, etc.).
parseItems: form-data field parseItems, boolean, optional, default false, whether to parse item lists (detail lines).
ReturnsApiResult<InvoiceOcrResult>: structured recognition result (invoice number, invoice date, total amount, remark, buyer/seller, etc.; standard fields in InvoiceOcrResult). Fails when the file is empty.

recognizeByFileId Recognize by attachment ID​

ItemContent
URLPOST /api/ocr/invoice/recognize/fileId
Paramsbody: body, Map<String,Object>, keys: fileId (required, invoice attachment ID; upload via /upload/file first to get one), parseItems (optional, default false, whether to parse item lists).
ReturnsApiResult<InvoiceOcrResult>: structured recognition result, same as above. Fails when fileId is blank.

health Engine health check​

ItemContent
URLPOST /api/ocr/invoice/health
ParamsNone
ReturnsApiResult<Boolean>: true means the invoice OCR engine is ready (missing dependencies count as not ready).

InvoiceOcrBackfillController — /ocr/invoice​

One-off batch invoice verification tool: re-recognizes the four invoice fields (number/date/amount/remark) of two business tables row by row and compares them with stored values, only marking differences without modifying the database.

backfill Batch invoice verification​

ItemContent
URLPOST /api/ocr/invoice/backfill
ParamsNone
ReturnsApiResult<Map<String,Object>>: data contains batchNo (batch number, yyyyMMddHHmmss) and results (one entry per verified table: table, total, matched, mismatched, failed, mismatches (difference details: column/label/dbValue/ocrValue), failures (recognition failures: table/rowId/fileId/reason)). The scope is fixed to rows with a non-empty file_id in il_invoice_req_file and il_payment_order_file; no update is executed at any point, so it is safe to re-run.
