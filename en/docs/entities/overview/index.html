Platform Entities Overview

geelato-meta is the module where the platform's business entities are centrally defined: the entities the platform itself needs to run — applications, organizations, users, roles and permissions, dictionaries, message notifications, file attachments, scheduling and integration — are all declared with the @Entity annotation in the module's cn.geelato.meta package, 54 in total. This chapter provides a field-level catalog, entity by entity, grouped by business domain; entities of other feature modules (business alerting, business exceptions, mail, etc.) are listed in the Platform Entity Index.

Module Position​

ItemDescription
Module coordinatesgeelato-meta (cn.geelato.meta package)
Upstream dependenciesgeelato-utils, geelato-lang (annotations), geelato-core (entity base classes and meta model)
Downstream consumersgeelato-web-common, geelato-web-platform, geelato-mcp-fms, geelato-mcp-platform
RegistrationZero manual registration: at startup MetaConfiguration scans @Entity classes under geelato.meta.scan-package-names (default cn.geelato) and registers them into MetaManager automatically

How entity metadata is parsed, cached and consumed (ORM SQL generation, MQL validation, datasource routing, etc.) belongs to the framework metadata mechanism; see Metadata Overview. For how to write entities with @Entity/@Col/@Title annotations, see ORM Annotations.

The entity inheritance chain is IdEntity → BaseEntity → BaseSortableEntity, with an extra common base class Attachment for the attachment domain (the base class itself is not a registered entity). The common fields below are not repeated in each entity's field table.

Enable Status (enable_status)​

enable_status is not part of the common base class. 9 entities implement the EntityEnableAble interface: Role, User, Dict, DictItem, SysConfig, Qrcode, ExportTemplate, UserEmailAccount, UserDelegateMap; values are 1 enabled, 0 disabled (default 1). Api, AppSqlMap and EncodingLog carry a same-named field without implementing the interface.

Storage Distribution (catalog)​

@Entity(catalog) decides which database an entity belongs to:

UnspecifiedArea, Compress, Message, Notice, Qrcode, UserStockMapResolved by the default datasource attribution rules; see Entity Binding & Priority

Conventions and Reading Notes​

  • The "Column" in each field table comes from @Col(name); fields without @Col derive their column name from the property name via camelCase-to-snake_case conversion.
  • Field meanings follow the field-level @Title (title + description) in the source code. A few class-level titles are distorted (e.g. Schedule's class title mislabeled as "应用" while it is actually a scheduled task; Tenant mislabeled as "租户站点"; UserStockMap contains "stock" in its name but actually means frequent contacts). This chapter documents actual semantics and notes the distortion in place.
  • Entities suffixed with *Map are relation tables (mappings between two tables) and usually carry few fields.
