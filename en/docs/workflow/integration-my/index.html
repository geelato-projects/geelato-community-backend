My Process Integration

This page documents, endpoint by endpoint, the APIs scoped to the current logged-in user: my pending tasks, done tasks, to-read, read, processes started by me, opinion phrases and circulation. The data scope is automatically the current user — no user parameter is needed (or accepted).

Common Conventions​

  • APIs use the unified /api prefix; response and pagination shapes are documented in Define Integration · Common Conventions.
  • All page queries support a unified keyword (keyword), server-side sorting (sortBy whitelist / sortOrder only asc / desc) and paging (page default 1, pageSize default 10).
  • Time parameters use yyyy-MM-dd HH:mm:ss; ranges are inclusive.

Common Response Structures​

MyTask​

Pending / done task entry:

FieldDescription
idTask id (use as taskId in the handling APIs)
procInstIdProcess instance id
procInstNameInstance name (【Definition Name】Business Name)
procDefNameProcess definition name
taskDefIdTask definition id (node id)
taskNameTask name
formRecordIdBusiness record id (businessKey)
descriptionTask description
assigneeId / assigneeNameHandler id / name (the current user)
ownerId / ownerNameInitiator id / name
createTimeInstance start time
arriveTimeTime the task arrived at the current node
finishTimeTask completion time (done list only)

ToReadVo​

To-read / read entry:

FieldDescription
idTo-read record id (use as id in the complete APIs)
procInstId / procInstNameProcess instance id / name
procDefNameProcess definition name
taskIdRelated process task id
formRecordIdBusiness record id
recipientId / recipientNameRecipient id / name (the current user)
senderId / senderNameSender id / name
commentCirculation comment
receiveTimeReceive time (yyyy-MM-dd HH:mm:ss)
readAtRead time (read list only)

My Pending Tasks​

GET /api/my/getMyPendingTask​

Lists all pending tasks of the current user (no paging).

Input (query):

ParameterTypeRequiredDescription
appIdstringNoFilter by definition's application; empty for all

Output (data[]): MyTask list.

GET /api/my/pageQueryMyPendingTask​

Page-queries the current user's pending tasks.

Input (query):

ParameterTypeRequiredDescription
keywordstringNoUnified keyword (instance name / task name fuzzy match)
appIdstringNoFilter by application
procDefKeysstringNoProcess types (definition keys), comma-separated
arriveTimeFrom / arriveTimeTostringNoArrival time range (inclusive)
stayLevelstringNoStay-duration bucket: lt8h under 8h / 8to24h 8-24h / gt24h over 24h
startUserIdstringNoFilter by initiator
sortBy / sortOrderstringNoSort field (e.g. arriveTime) / direction
page / pageSizeintNoPaging, default 1 / 10

Output (data): PageResult; data[] holds MyTask rows. total is computed with the same criteria, so paging is consistent.

Response example:

{
  "code": 200, "status": "success", "msg": "success",
  "data": {
    "page": 1, "pageSize": 10, "total": 1,
    "data": [
      {
        "id": "6001", "procInstId": "5001",
        "procInstName": "【Leave Application】Alice's leave request",
        "procDefName": "Leave Application", "taskDefId": "audit_1", "taskName": "Manager Approval",
        "formRecordId": "LV202611150001",
        "assigneeId": "u_2001", "assigneeName": "Bob",
        "ownerId": "u_1001", "ownerName": "Alice",
        "createTime": "2026-11-15 10:00:00",
        "arriveTime": "2026-11-15 10:05:00", "finishTime": null
      }
    ]
  }
}

My Done Tasks​

GET /api/my/getMyCompleteTask​

Lists all done tasks of the current user (no paging).

Input (query): appId (string, optional, filter by application).

Output (data[]): MyTask list (with finishTime).

GET /api/my/pageQueryMyCompleteTask​

Page-queries the current user's done tasks.

Input (query):

ParameterTypeRequiredDescription
keywordstringNoUnified keyword
appIdstringNoFilter by application
procDefKeysstringNoProcess types, comma-separated
finishTimeFrom / finishTimeTostringNoCompletion time range (inclusive)
durationLevelstringNoHandling-duration bucket: lt1h under 1h / 1to8h 1-8h / 8to24h 8-24h / gt24h over 24h
startUserIdstringNoFilter by initiator
sortBy / sortOrderstringNoSort field (e.g. finishTime) / direction
page / pageSizeintNoPaging, default 1 / 10

Output (data): PageResult; data[] holds MyTask rows.

My To-Read​

GET /api/my/getMyToRead​

Lists all to-read items of the current user (no paging).

Input (query): appId (string, optional).

Output (data[]): ToReadVo list.

GET /api/my/pageQueryMyToRead​

Page-queries the current user's to-read items.

Input (query):

ParameterTypeRequiredDescription
keywordstringNoUnified keyword
appIdstringNoFilter by application
procDefKeysstringNoProcess types, comma-separated
receiveTimeFrom / receiveTimeTostringNoReceive time range (inclusive)
senderIdstringNoFilter by sender
stayLevelstringNoTo-read stay bucket: lt8h / 8to24h / gt24h
sortBy / sortOrderstringNoSort field / direction
page / pageSizeintNoPaging, default 1 / 10

Output (data): PageResult; data[] holds ToReadVo rows.

My Read​

GET /api/my/getMyCompleteRead​

Lists all read items of the current user (no paging).

Input (query): appId (string, optional).

Output (data[]): ToReadVo list (with readAt).

GET /api/my/pageQueryMyCompleteRead​

Page-queries the current user's read items.

Input (query): same as My To-Read page query, plus:

ParameterTypeRequiredDescription
readAtFrom / readAtTostringNoRead time range (inclusive; read list only)

Output (data): PageResult; data[] holds ToReadVo rows.

Started by Me​

GET /api/my/getMyStart​

Page-queries process instances started by the current user (initiator fixed to the current user).

Input (query): same as the instance page query (status / procDefKeys / time ranges / sorting / paging); startUserId need not be passed.

Output (data): PageResult; data[] holds ProcInstListVo rows.

Opinion Phrases​

The current user's personal opinion phrases for quick input in the opinion box; data belongs to the current user and is visible/editable only by them.

GET /api/my/getOpinionPhraseList​

Lists the current user's opinion phrases. No input.

Output (data[]):

FieldDescription
idPhrase id
textPhrase text
enabledWhether enabled: 0 disabled (hidden from the opinion box) / 1 enabled
sortOrderSort order, ascending (smaller first)

POST /api/my/saveOpinionPhrase​

Creates an opinion phrase (empty id creates, otherwise updates; owned by the current user).

Input (JSON body):

FieldTypeRequiredDescription
textstringYesPhrase text
enabledintNo0 disabled / 1 enabled
sortOrderintNoSort order

Output (data): the saved phrase (with id).

PUT /api/my/updateOpinionPhrase​

Updates an opinion phrase (partial update of text/enabled/sortOrder; id required and must be owned by the current user).

Input (JSON body): as in create, plus id (string) required.

Output (data): the updated phrase.

DELETE /api/my/deleteOpinionPhrase​

Deletes an opinion phrase (logical delete; must be owned by the current user).

Input (query): id (string, required).

Output (data): "success".

Circulation​

Send To-Read​

POST|GET /api/toRead/sendToRead​

Sends the process instance to selected people for reading; one to-read item is created per recipient.

Input (query or form):

ParameterTypeRequiredDescription
procInstIdstringYesProcess instance id
taskIdstringNoRelated task id
recipientIdsstringYesRecipient user ids, comma-separated
commentstringNoCirculation comment

Output (data): result description string.

Rules: only people related to the instance (initiator / handler / past handler) may circulate; the action is recorded in the trace (CIRCULATE).

Complete To-Read​

POST|GET /api/toRead/completeRead​

Marks one of the own to-read items as read.

Input (query or form):

ParameterTypeRequiredDescription
idstringYesTo-read record id (ToReadVo.id from the to-read list)

Output (data): result description string.

Batch Complete To-Read​

POST|GET /api/toRead/batchCompleteRead​

Marks several of the own to-read items as read.

Input (query or form):

ParameterTypeRequiredDescription
idsstringYesTo-read record ids, comma-separated

Output (data): number of items completed.
