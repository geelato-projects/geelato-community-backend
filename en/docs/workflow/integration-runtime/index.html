Runtime Integration

This page documents, endpoint by endpoint, all runtime APIs: process start, next-step and participant resolution, task submission and handling, instance/task queries, instance management and reminding. The behavioral semantics (when to call what, how resolution works) are described in Workflow Runtime.

Common Conventions​

  • All APIs use the unified /api prefix and the {code, status, msg, data} response (see Define Integration · Common Conventions).
  • Paginated responses carry data as {page, pageSize, total, data[]}.
  • Key business codes: 400 task not found / instance not exist / parameter error; 403 no permission; 409 the task has been processed, refresh and retry (concurrent submission); 4031 no permission to view the process instance (insufficient data permission; front ends show a unified block).

Instance Status and Action Types​

Instance status (status):

ValueDescription
runningIn progress
completedCompleted (reached the end node normally)
terminatedTerminated (force-ended)

Trace action types (actionType):

ValueDescription
INITIATEStart
SUBMITSubmit
WITHDRAWWithdraw
TRANSFERTransfer
TERMINATE / FORCE_ENDTerminate / force end
DELETEDelete
CIRCULATECirculate
REMINDRemind
CANCELCancelled sibling tasks after a countersign denial

Common Response Structures​

NextStep​

The core structure of next-step / submit routing; it appears in the queryNextStep* responses and the runWorkflow input:

FieldDescription
stepNameStep name (e.g. "Submit")
stepTargetNameTarget node name
targetRefTarget node id, passed back as-is at submit
stepUserListCandidate handlers (StepUser); passed back at submit, may be trimmed to assigneeLimit
isAgreeWhether the step's flow is an agree line: 1 agree, 0 deny
assigneeLimitHandler count limit of the target node (0 unlimited)
subStepListParallel sub-steps (one entry per branch on parallel fork; same structure)
routeTargetRefsRoute target id chain (includes traversed gateway/automatic nodes); passed back as-is at submit
pathTextPath text (flow names, or current->next1->next2... when names are missing)
needAssigneeWhether handlers must be picked: true for user tasks; false for end nodes / parallel joins (submit directly)

StepUser​

Handler entry:

FieldDescription
userIdUser id
userNameUser name
enNameEnglish name
orgId / orgNameDepartment id / name

WorkflowInstance​

Instance detail (returned by the start APIs and the instance detail API):

FieldDescription
procIdProcess instance id
procNameInstance name (【Definition Name】Business Name)
defineKeyUnique definition identifier
bizId / bizNameBusiness id / name
statusInstance status: running / completed / terminated
startUserId / startUserNameInitiator id / name
createTime / finishTimeStart / finish time (yyyy-MM-dd HH:mm:ss)
currentWorkflowTasksCurrent active tasks (WorkflowTask)
formPageUrlForm page url (for read-only viewing)
withdrawableWhether the current user can withdraw
withdrawTaskIdWithdrawable task id; use it for the withdraw action
remindableWhether the current user can remind (initiator + running + active tasks + past the remind interval)
hasMyPendingTaskWhether the current user has a pending task on this instance
relationsCurrent user's relations to the instance: initiator / pending / completed / toRead / read
canHandleWhether the current user can handle it (own active pending task exists)
readonlyRead-only for the current user (complement of canHandle)
currentTaskIdThe current user's own pending task id
currentNodeCurrent node name
currentHandlersHandlers of current active tasks (WorkflowTask)
countersignProgressCountersign progress (CountersignProgressVO); empty when no countersign nodes

WorkflowTask​

Task / handler entry:

FieldDescription
procIdProcess instance id
taskIdTask id
taskNameTask name
userId / userNameHandler id / name
orgId / orgNameHandler department id / name
fromTaskSource task (nested, for tracing)

TaskInfoVo​

Task detail (returned by getTaskInfo / getCurrentTask):

FieldDescription
idTask id
nameTask name
procIdProcess instance id
procDefIdProcess definition id
assigneeHandler id
nodeInfoNode definition (Process Node structure incl. properties; drives buttons / opinion box / attachment area)
statusTask status
readOnlyRead-only flag (to-read scenarios)
bizIdBusiness data id (businessKey)
formPageUrlForm page url (node page property first, then definition pageId, then the default form url config)
needNextStepWhether submitting this task requires next-step/handler picking: true only when the multi-instance/countersign submitter is the last one and the submission completes the node
countersignProgressCountersign progress (empty for non-countersign tasks)

CountersignProgressVO​

Countersign node progress (countersignProgress[] of the instance detail and the task detail):

FieldDescription
nodeId / nodeNameCountersign node id / name
total / completed / approved / rejected / pendingExpected votes / completed / approved / rejected / pending
nodeStatusNode status: running / completed
arriveTime / finishTimeNode arrival / completion time
items[]Per-person detail: {userId, userName, dept, status(pending/approved/rejected/not_arrived), arriveTime, comment, endTime}
groupSource / groupInnerRule / countingUnitGrouped-countersign config echo (empty when ungrouped)
groups[]Group progress: {key, name, source, result(pending/agreed/rejected/skipped), total, agree, reject, skipped, members[]}; members share the items[] structure

ActivityTraceVO​

Trace entry (returned by getProcessTrace):

FieldDescription
nodeId / nodeNameNode id / name
activityTypeNode type (see Node Types)
startTime / endTime / durationStart / end time / duration
statusNode processing status
userId / userNameHandler id / name
commentComment
actionTypeAction type, see Action Types
attachments[]Attachments bound to this action: {id, name, size, kind(file/image), contentType, fileUrl, uploader, uploaderName, uploadTime, taskId, procInstId, nodeId, actionId}
countersignProgress[]Countersign progress of the node (empty for non-countersign nodes)

ProcInstListVo​

Instance list row (shared by the instance page query and "started by me"):

FieldDescription
procInstIdProcess instance id
procInstNameInstance name (【Definition Name】Business Name)
procDefNameProcess definition name
formRecordIdBusiness record id (businessKey set at start)
startUserId / startUserNameInitiator id / name
currentNodeCurrent node name (empty for finished instances)
currentHandlers[]Current handler names (empty for finished instances)
statusInstance status: running / completed / terminated
startTime / finishTimeStart / finish time (finishTime empty while running)

Process Start​

Start Process​

POST /api/engine/startWorkflow​

Starts an instance from the activated version; the instance stays on the initiate node and a draft pending task is created for the initiator.

Input (JSON body):

FieldTypeRequiredDescription
defineKeystringYesProcess definition key
bizIdstringYesBusiness id (stored as the instance businessKey for lookup)
bizNamestringYesBusiness name (instance name is 【Definition Name】Business Name)
formDataobjectNoBusiness form data, written into process variables for condition evaluation and form echo
attachIdsstring[]NoAttachment ids uploaded at start, bound to the start action record

Output (data): WorkflowInstance; currentWorkflowTasks holds the initiate-node task.

Request example:

{
  "defineKey": "leave_apply",
  "bizId": "LV202611150001",
  "bizName": "Alice's leave request",
  "formData": { "days": 3, "reason": "annual leave" }
}

Response example:

{
  "code": 200, "status": "success", "msg": "success",
  "data": {
    "procId": "5001", "procName": "【Leave Application】Alice's leave request",
    "defineKey": "leave_apply", "bizId": "LV202611150001", "bizName": "Alice's leave request",
    "status": "running", "startUserId": "u_1001", "startUserName": "Alice",
    "createTime": "2026-11-15 10:00:00", "finishTime": null,
    "currentWorkflowTasks": [
      { "procId": "5001", "taskId": "6001", "taskName": "Apply",
        "userId": "u_1001", "userName": "Alice", "fromTask": null }
    ]
  }
}

Errors: 400 definition not found or not published (no activated version).

Start and Submit​

POST /api/engine/startWorkflowAtomicity​

Starts the instance and submits the initiate node in one call, flowing straight to the next node.

Input (JSON body): the Start Process input plus:

FieldTypeRequiredDescription
selectStepListarrayYesNext-step selection (NextStep array), from queryNextStepPrediction / queryNextStep
commentstringNoInitiate-node comment, written into the operation record

Output (data): WorkflowInstance; currentWorkflowTasks holds the tasks after the flow.

Start Debug Process​

POST /api/engine/startDebugWorkflow​

Starts an instance from the debug (debug) version; behavior, input and output match Start Process. Returns 400 when the definition has no debug version.

Debug Start and Submit​

POST /api/engine/startDebugWorkflowAtomicity​

Starts and submits from the debug version; matches Start and Submit.

Next-Step and Participant Resolution​

Query Next Step​

GET|POST /api/engine/queryNextStep​

Resolves the reachable next nodes and candidate handlers for a running instance's task.

Input (query):

ParameterTypeRequiredDescription
procIdstringYesProcess instance id
taskIdstringYesProcess task id
isAgreeintNoFilter outgoing flows by conclusion: 1 agree lines only, 0 deny lines only; omit for all

Output (data[]): NextStep list. On a parallel fork each branch is returned as targetRef + subStepList.

Errors: 400 process instance not found / task not found.

Predict Next Step Before Start​

GET|POST /api/engine/queryNextStepPrediction​

Before the process is started, predicts the first stop after the initiate submission, by definition.

Input (query + body):

ParameterTypeRequiredDescription
defineKeystringYesProcess definition key
debugbooleanNoPredict by the debug version, default false
formDataobjectNoDraft form data (JSON body) for condition-line evaluation; may be empty

Output (data[]): NextStep list.

Query Next-Step Users​

GET|POST /api/engine/queryStepUser​

Resolves candidate handlers of a target node on a running instance.

Input (query):

ParameterTypeRequiredDescription
procIdstringYesProcess instance id
targetRefstringYesTarget node id

Output (data[]): StepUser list.

Predict Handlers Before Start​

GET|POST /api/engine/queryStepUserPrediction​

Before the process is started, predicts candidate handlers of a node, by definition.

Input (query):

ParameterTypeRequiredDescription
defineKeystringYesProcess definition key
targetRefstringYesTarget node id
debugbooleanNoResolve by the debug version, default false

Output (data[]): StepUser list.

Get Draft Form Page Url​

GET|POST /api/engine/getDefineFormPageUrl​

Returns the form page url bound to the definition, for loading the business form in an iframe before starting.

Input (query):

ParameterTypeRequiredDescription
defineKeystringYesProcess definition key
debugbooleanNoResolve by the debug version, default false

Output (data): form page url string (computed from the definition pageId and the default form url config, template like http://host/{pageId}?bizId={bizId}).

Task Submission and Handling​

Run Task​

POST /api/engine/runWorkflow​

Submits the current task and drives the flow — the unified entry for approval / handling / initiate submission.

Input (JSON body):

FieldTypeRequiredDescription
procIdstringYesProcess instance id
taskIdstringYesCurrent task id (must be the current user's pending task)
selectStepListarrayYesNext-step selection (NextStep array); pass back targetRef, stepUserList, routeTargetRefs, subStepList from the resolution APIs; stepUserList may be empty when the target needs no picking
commentstringNoApproval comment, written into the operation record
attachIdsstring[]NoAttachment ids bound to this submission

Output (data): "The Workflow Operate Success!".

Request example:

{
  "procId": "5001",
  "taskId": "6001",
  "comment": "Agreed, please follow the policy",
  "selectStepList": [
    {
      "stepName": "Submit",
      "stepTargetName": "Manager Approval",
      "targetRef": "audit_1",
      "isAgree": 1,
      "assigneeLimit": 1,
      "needAssignee": true,
      "stepUserList": [
        { "userId": "u_2001", "userName": "Bob", "orgId": "o_10", "orgName": "Engineering" }
      ]
    }
  ]
}

Rules:

  • The task must belong to the current user and not be suspended, otherwise 400/403.
  • Countersign: when one person votes deny (selectStepList contains isAgree=0), sibling pending tasks of the same node are cancelled and the deny line is followed.
  • Concurrent submissions of the same task are retried inside the transaction; after exhausting retries the engine returns 409 The task has been processed, please refresh and retry.
  • When the target node has no explicitly picked users, the engine resolves participants from the node assignee config; on an empty result the node's emptyAssigneeStrategy applies (see Workflow Orchestration · Empty Participant Strategy).

Withdraw​

POST /api/engine/withdraw​

The initiator withdraws a sent-out process; the process returns to the initiator's pending list.

Input (query):

ParameterTypeRequiredDescription
procIdstringYesProcess instance id
taskIdstringYesTask id to withdraw (take withdrawTaskId from the instance detail)
commentstringYesWithdrawal reason, written into the operation record

Output (data): result description string.

Rules: only completed tasks with no later node processing record can be withdrawn; the instance detail's withdrawable is the visibility flag.

Reject to Previous Step​

POST /api/engine/rejectToLastStep​

Returns the process to the previous processing node.

Input (query): procId (string, required), taskId (string, required, current task id), comment (string, required).

Output (data): result description string.

Reject to Start​

POST /api/engine/rejectToStart​

Returns the process to the initiate node; the initiator edits and resubmits.

Input (query): same as Reject to Previous Step (procId, taskId, comment).

Output (data): result description string.

Reject to Node​

POST /api/engine/rejectToNode​

Returns the process to any specified node.

Input (query):

ParameterTypeRequiredDescription
procIdstringYesProcess instance id
taskIdstringYesCurrent task id
targetNodeIdstringYesTarget node id to return to
commentstringYesReject comment

Output (data): result description string.

Transfer Task​

POST /api/engine/transferTask​

Hands the own pending task to another user.

Input (query):

ParameterTypeRequiredDescription
taskIdstringYesTask id
userIdstringYesTarget user id
commentstringNoTransfer comment

Output (data): result description string.

Instance and Task Queries​

Get Current Tasks​

GET /api/engine/getCurrentTask​

Lists all active tasks of an instance.

Input (query): procId (string, required).

Output (data[]): TaskInfoVo list.

Get Instance Detail​

GET /api/engine/getProcInstance​

Returns the instance detail. Running instances return runtime data; finished instances (no runtime state) are reconstructed from history so the detail page still renders.

Input (query): procId (string, required).

Output (data): WorkflowInstance.

Error: 4031 no permission to view the process instance (insufficient data permission).

Get Instance Tasks​

GET /api/engine/getProcTask​

Lists all tasks of an instance (with handler info).

Input (query): procId (string, required).

Output (data[]): WorkflowTask list.

Get Task Detail​

GET /api/engine/getTaskInfo​

Returns the task detail by task id (node definition, form page url and submit hints included).

Input (query): taskId (string, required).

Output (data): TaskInfoVo.

Page-Query Process Instances​

GET /api/engine/pageQueryProcInst​

Page-queries process instances. Data permission: admins see everything; non-admins only see instances related to them (started by me / my pending / my done / my to-read and read).

Input (query):

ParameterTypeRequiredDescription
keywordstringNoUnified keyword (instance name / definition name fuzzy match)
namestringNoName fuzzy match (legacy parameter)
statusstringNoInstance status: running / completed / terminated
statusListstringNoStatuses comma-separated (e.g. completed,terminated); takes precedence over status
appIdstringNoFilter by definition's application
procDefKeysstringNoProcess types (definition keys), comma-separated
startUserIdstringNoFilter by initiator
startTimeFrom / startTimeTostringNoStart time range (yyyy-MM-dd HH:mm:ss, inclusive)
finishTimeFrom / finishTimeTostringNoFinish time range
currentAssigneeIdstringNoCurrent handler id (running instances)
currentTaskDefKeystringNoCurrent node id (running instances)
sortBy / sortOrderstringNoSort field (server-side whitelist) / direction asc / desc
page / pageSizeintNoPaging, default 1 / 10

Output (data): PageResult; data[] holds ProcInstListVo rows.

Get Process Trace​

GET /api/engine/getProcessTrace​

Returns node-level operation records of an instance (data source of the process timeline).

Input (query): procId (string, required).

Output (data[]): ActivityTraceVO list.

Error: 400 history not exist (instance has no history).

Get Instance BPMN​

GET /api/engine/getProcBpmn​

Returns the BPMN XML of the instance's definition, for read-only process diagram rendering; finished instances are served from history.

Input (query): procId (string, required).

Output (data): BPMN XML string.

Get Instance Form Data​

GET /api/engine/getProcFormData​

Looks up process variables (form data) by business id.

:::warning For testing only Form data should normally be provided by the business system per bizId; this API is kept for integration demos. :::

Input (query): bizId (string, required).

Output (data): process variable key-value object.

Instance Management​

Force End​

POST /api/engine/forceEndProcInstance​

Force-terminates a running instance; all unfinished tasks are terminated and the instance becomes terminated.

Input (query): procId (string, required), comment (string, optional).

Output (data): result description string.

Delete Instance​

POST /api/engine/deleteProcInstance​

Deletes the instance with its tasks and operation records; business data is unaffected.

Input (query): procId (string, required), comment (string, optional).

Output (data): result description string.

Reminding​

Get Remind Targets​

GET /api/engine/remindTargets​

After verifying the current user is the initiator, returns the deduplicated handlers of the instance's active tasks and the default remind text.

Input (query): procId (string, required).

Output (data[]):

FieldDescription
userId / userNameHandler id / name
defaultContentDefault remind text

Error: 400 the current user is not the initiator / instance not running.

Send Remind​

POST /api/engine/remind​

The initiator sends a remind to the specified handlers.

Input (query):

ParameterTypeRequiredDescription
procIdstringYesProcess instance id
userIdsstringYesTarget user ids, comma-separated
contentstringNoRemind text; the default text is used when empty

Output (data): result description string.

Rules: only the initiator can remind, and the remind interval must have elapsed (the instance detail's remindable is the visibility flag).
