# 应用包部署

本页说明应用包到达目标环境后的部署流程：入口与环境门禁、部署前校验、备份与回滚、落库策略、生效机制与失败行为。部署入口为版本管理页的"部署"操作，对应端点 `GET /package/deploy/{versionId}`（按 `geelato.package.engine` 分流）。

## 部署前校验

部署请求按以下顺序执行校验，任一步失败即终止，不产生任何数据变更：

1. **环境门禁**：`geelato.package.env` 为 `init_source` 的环境禁止部署（60010），防止初始化源环境被反向覆盖。
2. **版本与包可读**：版本记录存在且 `packagePath` 有效；`.zgdp` 按压缩包读取（附件标识经文件服务解析），包内无元数据时报 60003。
3. **元模型兼容**：包内每个 `metaName` 必须在目标平台的 `MetaManager` 中存在对应实体定义；每行每列必须能解析到字段元数据。任一不满足即报 60004，提示"请先更新平台应用 geelato_admin 至版本 X"（X 为包的 `basePlatformVersion`）。

:::note 60004 的实际含义
校验比对的基准是**目标平台当前的元模型**，不是简单比较版本号字符串。报 60004 表示包内出现了目标平台实体定义中没有的表或列——通常因目标平台版本过低或源环境表结构未同步，按提示升级平台应用 `geelato_admin` 后重试。
:::

## 备份与回滚

- **自动备份（仅 v2）**：部署非备份版本前，自动把目标应用当前数据打包为一个备份版本（版本号追加 `_backup`，状态 `backup`）。备份独立提交，部署失败时备份仍在。
- **回滚**：`GET /package/rollback/{appId}` 取最近一次备份版本重新部署（备份版本部署时不再生成新备份）。v1 引擎不产生真实备份，回滚会提示未找到备份版本。

## 落库策略

部署落库把包内每张表写入目标库，按"增量表"与"覆盖型表"区分两种策略。增量表 = 5 张平台增量表（`platform_dict`、`platform_dict_item`、`platform_sys_config`、`platform_encoding`、`platform_resources`）∪ `pack_bus_data=1` 的业务表；其余为覆盖型。

| 策略 | 适用表 | 删除阶段 | 插入阶段 | 语义 |
| --- | --- | --- | --- | --- |
| 覆盖型 | 页面、菜单、模型、数据源、角色/权限、导出模板等 | 按 `app_id` 清空本应用旧行（`platform_app` 按 `id`、`platform_tree_node` 按 `tree_id`） | 插入包内全部行，主键保留原值 | 包内容**替换**目标环境本应用数据 |
| 增量型 | 5 张平台增量表 + `pack_bus_data=1` 业务表 | 不删除 | 插入包内行，目标库已存在同 `id` 的行跳过 | **幂等合并**，可重复部署补齐 |

所有插入保留包内原主键（`forceId` 语义），保证页面-菜单-模型等跨表引用关系在部署后仍然成立。落库按 **500 行/批** 分批执行（MQL `SaveCommand` 链路，序列化启用 `LargeObject` 以支撑大表），批次间不整表往返序列化，避免大包内存溢出。

### 失败行为

- **v1**：删除与插入包在一个编程式事务内，任一元数据处理失败（未知实体/列硬失败 60005）整体回滚，目标库保持部署前状态。
- **v2**：分批落库，未知实体/列跳过并记录警告日志；中途失败时已写入的批次保留，不会整体回滚。增量表重新部署按已存在 `id` 跳过、可安全重放；覆盖型表重新部署即整体替换，可自行补齐。

:::warning 部署失败的处置
v2 部署失败后不要直接修补数据：优先查看 `${LOG_DIR}/pack/` 定位失败表与原因，修正后**重新部署同一版本**——覆盖型表会整体替换、增量表按 id 幂等跳过，重复部署收敛到一致状态。
:::

## 部署后生效

落库成功后按应用刷新运行期元数据（`refreshDBMeta` 逐实体重载）并失效相关查询缓存，**热加载生效，不需重启平台**。页面、字典、配置类数据按需查库并走缓存，部署后访问即新数据。

元数据缓存刷新失败时报 60009（"应用数据已部署成功，但刷新应用元数据缓存失败"），数据已落库、部署不回滚，按日志提示处理后重载即可。

## 部署错误码速查

错误码定义在 `PackException`（60xxx 段）：

| 码 | 场景 | 含义 |
| --- | --- | --- |
| 60001 | 打包 | 应用不存在 |
| 60002 | 打包 | 打包前列一致性校验不通过，禁止打包 |
| 60003 | 部署 | 版本/包数据缺失或损坏 |
| 60004 | 部署 | 元模型校验不通过，需先升级平台应用 `geelato_admin` |
| 60005 | 部署 | 元数据或字段在目标平台不存在（v1 硬失败） |
| 60006 | 部署 | 包数据写入失败 |
| 60007 | 通用 | 表名非法（防注入校验不通过） |
| 60008 | 通用 | 包文件读写失败 |
| 60009 | 部署 | 部署成功但元数据缓存刷新失败 |
| 60010 | 通用 | 环境限制不允许操作 / 回滚无备份版本 |

## 日志排查

打包与部署全部日志按包名 `cn.geelato.web.platform.srv.pack` 独立路由到 `${LOG_DIR}/pack/`（按日期滚动，不向主日志扩散），内容包括：每次打包/部署的起止与耗时、每表打包行数、每条删除 SQL、每批落库与跳过的实体。排查部署差异时，先比对日志中"每表行数"与包内预期。
